# RPE 1.5：JSON 候选与无人值守闭环

用户授权继续目标模式，先建立 JSON 专用验收，跑通自动升级和回滚，再无人值守验证，收尾清理本轮资源。基线1c81ee4/v1.4.0，干净checkout中使用codex/rpe-v1.5。沿用单一SQLite、CAS/lease、宿主外固定CLI和候选沙箱，无新依赖/分类器/常驻服务。设计选择为扩展现有生命周期；另建JSON运行时会重复权威，仅允许手工升级则无法满足本轮自动闭环。

## 候选与可信验收

新增executor:json_executor、recipe:json_recipe，ABI prepare(plan, staging_path)不变。代码仅标准库，不读取RPE/oracle/heldout。JSON生产每次重新使用既有独立JSON oracle和手写literal fixtures。候选源64KiB、输入1MiB、输出16MiB、深度64/token100000/数字256；每fixture最多3秒，macOS单层sandbox与128MiB RSS软阈值沿用，不声称瞬时硬内存限制。CSV沙箱源读取也改为读取时即16MiB限制。

专用json_acceptance模块：独立手写bytes fixtures（train和heldout），覆盖双style、六类顶层类型、嵌套/空容器、词法数值/escape/顺序、边界；拒绝重复解码key、BOM、非有限值、非法UTF8/代理码位、尾随/截断、深度/token/数字超限。非法JSON fixture绕过正常admission直接调用候选，必须观察候选明确解析拒绝；超时/RSS/沙箱缺失和oracle否定产物不能伪装成功拒绝。字节预算准入拒绝另标admission，不冒充candidate_invoked。

JSON recipe仅含capability/input_format/style/constraints/procedure，固定procedure=[plan,prepare,independent_verify,exclusive_publish]；不替换oracle。代码和recipe都跑专用suite，recipe使用可信内置writer，标明不同执行来源。证书绑定kind、capability、合同/producer/oracle/fixture/acceptance/sandbox修订、资源与证据hash；JSON证据只可支持JSON候选，CSV候选只可用CSV证据。CSV/recipe default current_revisions()与证书旧结构保持兼容，JSON使用current_revisions(kind)。签名Registry本轮仍支持既有CSV ABI；JSON导出保持拒绝，不借用CSV来源证书。

专用模块接口：JSON_KINDS、_FIXTURES、current_revisions()、replay_acceptance(store,content,kind,timeout=3.0)、complete_certificate(report)、prepare_code(plan,content,root,timeout=3.0)、recipe_valid(recipe)。sandbox.resource_limits(capability=None)保留默认CSV，JSON参数返回1MiB；run_candidate按明确plan.capability/format选择预算，不接受任务提高。CandidateRejected区分候选明确拒绝和环境/资源失败，拒绝fixture不得将未知异常当解析拒绝。

## 自动闭环与回滚

同一candidates模块按精确kind分派验收/证书/生产槽；JSON代码优先，匹配的JSON recipe次之，否则内置。实际candidate/recipe version/hash进入现有artifact与持久步骤，oracle失败先记录candidate_fallback，再按同一plan内置执行和独占发布。隔离当前active时，从其applied snapshot找到前版本，重新确认当前证书、代码和新鲜证据：有效则原子恢复前版本；无效/隔离则回builtin。当前任务仍走builtin，不在同次失败中递归执行前版本。CAS手动rollback和activation intent/commit崩溃恢复沿用。

cycle默认从verified JSON反馈生成按style/constraints聚合的声明配方及经验；外部proposer可返回json_executor代码提案，自动专用验收和apply。报告origin区分default_verified_recipe、default_diagnostic、external_injected_code，注入测试代码不叫自主写代码。相同active内容且证书有效不因新证据集合增长再激活；初始证据失效仍隔离。成功builtin fallback中的失败candidate_fallback步骤也进入结构化diagnosis，不靠关键词分类。

独立CLI Agent可用现有evolution propose提交json_executor；cycle在同一提案预算内消费DB中proposed/validated的JSON代码提案，origin=external_persisted_proposal。保持原immutable指纹与证据，只通过可信验证及CAS激活；applied/quarantine跳过，过时提案拒绝可观察。配方单槽保持当前有效且匹配反馈组的版本；其他style仅验证不自动来回切槽，无active时稳定首组激活。

维护预算固定：cycle(max_proposals=32,max_history_runs=100)，参数必须正整数且不超过默认硬界限；历史超预算在任何维护变更前失败，生成提案总数超预算拒绝，不静默跳过。这是有界本地维护batch，不声明永久服务级无界历史支持。JSON新类型/宿主/core/verifier仍诊断提案，不能降低标准自动升级。

## 无人值守验收与交付

新增固定轮数driver，显式owned-root/candidate_path；每task/cycle/activation故障都独立进程，持续保存progress，失败保留returncode/type/阶段。默认JSON配方自动生成/验收/激活，重复循环不变；显式外部代码提案自动验收/激活、新pretty/minify任务实际复用；activation intent崩溃恢复aborted和commit后保留applied；production-only错误产物隔离/same-plan builtin、后续恢复previous；无效前版本回builtin；手动rollback；JSON经验休眠再寻址。总轮数/进程/每步timeout有硬预算。

这是预设候选来源的无人工干预状态机验证，不预先宣称长期学习因果收益或自主生成高质量代码。至少安装后重跑driver和真实Hermes JSON候选pretty/minify；以字节真值、实际版本/hash、gate/usage/进程清理为验收。完整回归一次、独立审查、源码/wheel/安装48+源文件核对；本地1.5.0提交与tag。只保留有限公开证据，清除本轮home/history/cache/私钥/DB/venv/进程，不清共享历史或重启日常服务。旧仓/日常设置按hash和Git状态核对。
