# RPE 1.10 自然语言要求审阅与确定性执行

用户已授权目标模式开发本地可用版本。保持独立 Harness、Hermes 首个宿主、三种既有能力，不新增分类器训练、常驻服务、自动批准或飞轮系统。

## 用户流程

自然语言任务经 Hermes 起草要求清单；终端展示完整原话、逐条要求和原文引用、建议默认值、缺项及不支持的条件。用户不需要编写 JSON。模型只有 rpe_propose 工具，不能确认或执行业务。用户通过可信本地 CLI 审阅并输入“确认”，或可信宿主通过绑定摘要的公共 API 确认。之后从不可变确认记录取出机器合同，沿用既有确定性执行、原生 XLSX helper、独立验收、原子发布及有界进程清理。

不声称任意自然语言语义完整性可以由程序证明。引用是出处证据，人工审阅是接受模型理解的边界。缺项、不支持条件和已知未映射要求必须阻止确认；模型遗漏但程序未识别的语义错误仍可能存在，完整原文与清单一起展示以供审阅。新增草案、澄清或修订生成新身份，旧确认不可套用。

## 最小接口

新增 proposal.py、proposal_cli.py，保持 requirements.py 的严格 JSON 语义不变。草案严格字段 capability、constraints、execution、requirements、unresolved。要求行字段 text、quote、fields；quote 为原文精确子串，或 null（明确展示为建议默认）；fields 为 /capability、/constraints、/execution/字段 的有限指针。父进程计算原文位置，覆盖每个机器字段，不采信模型“已确认”或“完整”的自述。源文及草案均不超过64KiB，最多32条要求。

create_proposal(raw,draft,db_path,workspace,session_id,source_ref,catalog_root,skill_snapshot_id) 持久保存原文、草案、可读清单、输入和目录绑定。ProposalStore 提供 show、confirm(expected_proposal_sha256,actor)、resolve、execute。确认与执行分别持久；在副作用前重新验证源、目录、输入和路径，原子消费单次执行权限，防止并发重复发布、重放和跨会话使用。确认记录是可信应用层操作，不是抵抗本机账户完全被控制的安全边界。

Hermes 新增 review 模式和 run_hermes_review 包装，只生成草案。复用 clean 的限定 transport 参数、父进程保存当前原文、固定目录与提示、实际 SDK 入口验证和异常跳过时的 fail-closed 保护。不得调用 clean 的自动执行 handler。模型不能访问批准记录、父进程数据库或其他会话。

## 对照及发布门槛

先做失败测试及针对性回归，最后一次完整回归、实际已安装 Hermes SDK 无网络验证、安装 wheel 独立验收与跨节点/篡改/并发检查。独立审阅不得由实现者自行替代。

真实模型实验独立于1.8/1.9数据：最多1对 pilot 和6对 formal，最多14次起草会话及7次原生执行会话，单任务不追加修复尝试。四个生产夹具（CSV、TAB、保留字面 token 的 JSON、原生 XLSX）与两个边界任务（缺键、不支持额外条件）。同模型、原文、公开能力/草案格式、依赖与技能；原生保留工具发现。双方草案均由预注册夹具审阅器仅接受/拒绝，不改写、不向模型注入标准答案。明确标注“模拟审阅”，不当成真人使用验证。原生确认后再调用原生宿主执行，RPE 直接确定性执行；比较整体流程，不能归因单一模块。

逐阶段预留持久账本，包含起草、模拟审阅、执行、验收、失败和 pilot 的全部可观测 token/API/耗时；真人审阅时间、账单和不可得缓存数值用 null。业务正确、要求忠实、确认绑定、完整链分别计分。代码、依赖、宿主、夹具、评分冻结后才运行付费实验，所有失败保留，不重评掩盖。

导出公开原文/夹具、经过验证的草案与要求引用、确认绑定、正确产物、成本及运行核验摘要；不保留私有模型历史、密钥或未知模型文本。清理后离线复验。只清理本轮 owned-root、登记进程和工作树；不回滚用户并行产生的日常 Hermes 状态。保留旧仓和既有未跟踪报告，交付本地版本/安装包/报告，不推送。

## 正式负结果后的单次契约修正（2026-10-15）

原pilot2次、正式12次起草全部保留，未批准任何生产任务；质量和总成本收益未成立。正式JSON两臂机器参数正确，却把固定默认值、运行检查、尚未确认本身写进unresolved；review另有能力ID混入说明文字。仅修正标准工具schema与两臂共享公开合同：给出精确ID、约束和字段指针选项，说明真实默认值、控制器运行前提与业务缺项的区别。父层验证不放宽，不清除或改写模型unresolved，不增加重试、分类器或训练。官方Hermes不执行schema enum语义验证；枚举是出站模型契约，父层检查仍是执行门槛。

新建独立、预先冻结的诊断后JSON冒烟，仅一对2次起草、最多1次原生执行；双方使用同一更新公开合同，不向模型提供正确字段或oracle，仍是一次候选接受或拒绝。追加上限使本轮最多16次起草、8次原生执行（最多24宿主会话）；旧14/7预算及成绩独立保存。本次仅用追加2/1额度，不自动耗尽未使用原额度。即使通过，也只证明这个已见JSON任务的真实链路可用，不能当作总体胜率或真人审阅证据。冒烟之后不再按成绩调整提示、修复候选或追加轮次。
