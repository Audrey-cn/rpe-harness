# RPE 1.8 统一能力目录与必要状态寻址

用户已批准按原稿复盘细化 todo 并直接以目标模式执行。本文落实已审核的 reports/direction-review-2026-10-15/原稿复盘与主体开发方向重审.md：保留独立 RPE 和唯一执行验收权威，优先寻址与状态，不另造 Hermes 飞轮。

## 交付边界

现有 tabular.deduplicate、json.normalize、xlsx.inspect 三能力构成有限交付范围。新增统一目录、任务理解接口、持久最小状态交接，以及真实 Hermes address 模式。Hermes 模型承担自然语言理解，规则与目录承担后续条件筛选；明确结构化输入不额外调用模型。无需新分类器训练、多 Agent 平台、任意 DAG 或新业务执行器。

统一目录只由可信内置定义注册执行能力。外部技能快照可提供发现条目和受审核 adapter 绑定，未注册技能明确 discovery_only。保留旧 route/skills 接口作兼容，但 1.8 CLI、HTTP 和 Hermes 地址路径使用同一目录快照。按 capability/format 建索引，常见明确能力查找不扫描全部描述。冷技能可发现，禁用/腐坏/无适配不能执行。目录和当前信任状态均可追溯，不能仅靠旧快照继续授权。

## 接口与状态

新 capability_catalog.py：CapabilityCatalog(skill_rows=())；snapshot_id 为内容摘要；entries() 返回 JSON 条目；resolve(capability=None,input_format=None,constraints=()) 返回 status、candidates、catalog_sha256、missing。status 为 ready/needs_context/unsupported/ambiguous。明确能力不由关键词分数改变。条目描述能力、格式、约束、必要执行字段、执行身份与 adapter 状态。

新 intent.py：interpret_intent(extracted, *, catalog, workspace, session_id, source_ref, source_facts=None) -> dict。extracted 为 {goal,capability,constraints,execution}，不接历史文本；输入字节和层级有界，不忽略未知字段。不支持、缺字段、来源冲突明确返回。执行参数遵循现有契约；路径限定 workspace，无 symlink。ready 包含精确 schema-v2 request、目录摘要、源输入 hash 与状态摘要。不会因分类/metadata 获得执行权。

MinimalStateStore(db_path).capture(result, *,session_id,source_ref) -> dict；resolve(state_id, *,session_id,catalog_sha256) -> dict。ready 状态持久不可变，绑定真实会话和来源，保存必要 request/来源摘要而非完整聊天。外部可见 handoff 只有 state_id、capability、constraints、catalog_sha256、status，不回传输入数据或历史。不同任务不能互用 state_id；完整性、目录/信任或源输入变化拒绝。可重复交接不重新生成业务参数。

## Hermes 接线

新增 entry_mode=address：rpe_understand 提交结构化提取 → 父进程 interpret/catalog 检查并持久最小状态 → rpe_task 仅提交 state_id → 父进程用已锚定参数调用既有执行/独立 oracle → 终态。第二节点不重写参数，解决同一参数在多跳反复转译。模型错误不能通过隐藏 required_request 自动修成正确答案；可选固定请求只作为已授权锚。

沿用原生身份、receipt、官方 middleware 和外部 broker。最多三次理解纠错；明确缺业务信息返回 needs_context，不猜列名、来源或约束。实际任务只有现有执行预算，结束后不能再次执行。新增阶段记录 metadata/hash，不导出私有参数正文。address 不运行自建 evolution cycle；学习、普通技能生命周期和调度由 Hermes 原生承担。测试 profile 禁止修改日常技能/记忆，避免对照中发生未登记升级；这是隔离条件，不宣称已测试长期飞轮。

## 原生对照

固定公开的小型 CSV/TSV、JSON、XLSX 自然请求及独立真值，含中文改写、明确参数、缺失/不支持和约束保留；最多 6 种任务×2臂=12个正式会话，另最多两次基础接线 pilot。原生拥有相同文件、依赖与技能资源，保留其已有搜索/渐进加载能力；address 只提供能力目录与两段接口。两组原始任务文本一致，不把结构化标准答案提供给模型。所有失败、pilot 和实际用量计入。

统计业务正确、契约忠实度、实际能力命中/调用证据、完整 token/API/wall、模型可见 handoff 字节。两策略工具政策不同，只能比较整体策略；不归因某单一模块。缺少 usage 则总量 null 并报已知下界，不把 token 当账单。冻结正式登记后不换代码、不扩预算、不重评失败；修后另登记只复核相关失败。不制造通用优势结论。

## 验收与清理

意义回归覆盖：未知能力/约束、相同格式不同目标、缺参数、source conflict、tampered/cross-session state、目录变化、冷技能和无 adapter、A→B→A与并发无串扰、输入变化、任务幂等。运行原有完整回归、安装 wheel 后独立 CLI 文件闭环和分支审查。

所有测试写入登记 owned-root；先导出公开证据和脱敏摘要，再精确停止登记进程/身份并移除 owned-root。日常 Hermes 配置与状态只比较摘要，外部漂移不盲目恢复。旧仓不改，原有未跟踪报告保留。版本1.8、报告、wheel及源码对齐后整合主项目，归档工作树。不推送远端、不添加常驻服务。
