# 1.12：有限参数、原文定位与公平原生证据

用户授权：继续目标模式提高真实任务稳定通过率，解决参数表达、引用与原生缺证；保持轻量并复用 Hermes，可调用本机任意 Agent 验证，清理本轮专属测试状态。

本轮沿用现有架构，只修复理解合同、明确来源寻址和宿主观测。RPE 独立，Hermes 为首个宿主；不新增分类器、记忆平台、常驻进程或 Python 运行依赖。可执行范围仍限现有三个契约。

## 决定

1. 起草 delimiter 复用公开 request_schema 的单字符约束；说明给出真正逗号和 TAB 的机器值。父层继续拒绝 comma、TAB、字面反斜杠 t、换行等非法值，不替模型修复执行参数。
2. 保留逐字 quote；增加可选 quote_ref 明确寻址。父层按当前原文整体和非空行生成确定性内容绑定标识，来源附件沿用已验证字段片段。引用标识只定位原有字节和字符范围，不作语义分类；未知标识或与 quote/source_ref 不一致继续拒绝。原始 draft 原样保存，审阅展示解引用后的文字和范围，确认/执行重验原有绑定。
3. 原生工具保持自由，观察真实 terminal/write_file/patch 的 draft.json 发布前后回执，绑定实际 API/工具身份、参数和文件摘要；不能靠命令提到文件名或最终回复里的 JSON 证明发布。原始请求与能力供给/来源附件明确分开。冷恢复验证真实已安装 curator CLI、技能前后字节和原生 skill_view，失败保留具体缺证原因。
4. Claude Code 只做一次独立审阅，工具关闭、独立配置/缓存目录、不保存会话，读取已有认证路由但不复制或修改凭据。当前路由为 MiMo，不能称 Claude 模型验证；审阅不产生执行权限，实际费用未核实则保持未知。

不选择模糊接受引用、静默参数修复或反复模型重试。它们难以保持用户原意和不可变提案。定位标识及单字符 schema 是现有边界内的直接修复。

## 验收与预算

先用安装的 Hermes 原生工具做无模型 smoke（真实文件发布和冷恢复），通过后冻结实际源代码/合同/输入、模型身份和独立 oracle。复用 1.11 的有界实验底座，仅增加显式 1.12 profile，不改变旧记录/评分。

一个 pilot 对和四个正式对：逗号 CSV、真实冷 XLSX（附件指定模式/表）、TAB CSV（附件指定复合键）、缺业务键拒绝。每个 trial 只起草一次；最多 10 次起草宿主和 5 次原生执行宿主，180 秒/8 轮起草，原生执行 120 秒/8 轮。仅语义审阅接受的原候选可执行；原生侧仍用原生工具，不能借 RPE 控制器完成任务。两臂相同业务输入、明确来源事实、技能供给、模型和公开合同；新 quote_ref 定位供给一致。

正式冻结后不修复草案、不重跑失败、不回填旧分数。任何需修改的生产代码都另记，不能把改后结果混入原冻结对照。一次 Claude Code 独立审阅限制 1 turn、180 秒、CLI 估计预算 0.25 USD，失败也留存，不自动重试。该估值不是提供商硬账单上限。

分别报告宿主/真实调用/来源映射/语义/确认/执行/独立产物及拒绝指标。成本包括 pilot、失败、正式和独立审阅；缺测不记零，不从低成功样本推导效率优势。工程开发模型与账单另外列口径。

## 状态保全

本轮专属根目录由 ownership.json 标识；HOME、历史、凭据副本、缓存、临时库、venv、CLI 探测和进程仅在有所有权的范围清理。旧报告、主仓原有未跟踪资料、旧仓、日常技能和认证变化不覆盖。保留脱敏公开证据、源码提交与 wheel，清理后离线复验。
