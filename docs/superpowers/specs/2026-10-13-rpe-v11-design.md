# RPE-Harness 1.1 Hermes integration

Goal: run the installed Hermes host with its real model and tools, link native lifecycle events to verified Harness runs, compare six fixed tasks against the same host without the Harness tool, and remove owned test state afterward.

Architecture: a native Python plugin registers `rpe_task` and synchronous metadata observers. `HostEventStore` uses a separate SQLite table alongside RunStore; host IDs remain distinct from generated ingestion IDs. The tool persists receipt, resolves paths inside an explicit workspace, invokes the compatible Harness Python via a subprocess, and returns compact JSON. Post-tool events link the real tool-call/API/turn IDs to the returned run ID. Missing native event IDs and usage stay unknown.

An isolated session launcher copies only the existing Xiaomi API key and plan URL into a private temporary home. It disables external plugins, MCP, memory, auxiliary calls and onboarding, launches installed Hermes Python with `-B`, and applies macOS filesystem and signal restrictions. It never copies OAuth state, changes daily configuration or restarts the gateway. Both comparison arms load the observer; the native arm disables only `rpe_task`.

Tech: Python >=3.10, sqlite3, openpyxl, installed Hermes v0.21.7 plugin API, macOS sandbox-exec. Product dependency remains openpyxl; host dependencies come from the installed Hermes environment.

Interfaces:
- `HostEventStore(path).record(kind, payload)` and `.list(session_id=None)` preserve allowlisted metadata only, including usage and run links.
- `register(ctx)` reads explicit RPE_HERMES_DB, RPE_HERMES_WORKSPACE, RPE_HARNESS_PYTHON and RPE_HERMES_TOOL_ENABLED. Tool name `rpe_task`, toolset `rpe_harness`, args `{request: <v1 envelope>}`.
- `run_hermes_session(prompt, workspace, db_path, *, tool_enabled, owner_root, timeout=180, hermes_root=None) -> dict` returns exit/completion, final response, session IDs, real host events, measured usage coverage and elapsed time. Own state stays below owner_root until caller cleanup.
- Experiment `build_cases(root)`, `validate_case(case, workspace, result)` and `run_comparison(root, report_path, session_runner)` use relative paths and byte-identical prompts across arms.

Acceptance: four CSV/XLSX successes and two deliberate rejections; input hashes unchanged, independently reopened artifacts correct, rejection reason present with no output. Integrated success requires an actual `rpe_task` call, linked durable run and verifier success. Native output is checked by the same external oracle plus manually specified truth. Alternate arm order, use identical model/provider/settings, report all attempts and unknown token fields. No claim of causal-graph or general-agent superiority from this small controlled sample.

Global constraints: never expose credentials; only owned temporary histories/caches/process groups can be deleted; fail if durable observations are missing. Preserve concise evidence and source, not full private session history. Do not alter installed Hermes code.

Review focus: containment/symlinks, event identity and deduplication, observer failure visibility, subprocess exit and timeout handling, provider usage ambiguity, fair fixtures and cleanup ownership.
