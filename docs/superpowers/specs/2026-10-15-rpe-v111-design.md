# RPE-Harness 1.11 设计与验收边界

用户已授权按本轮考古结论实施。RPE 保持独立、Hermes 是首个宿主；不合并旧仓库、不增加分类器或新服务。

## 本轮交付
1. 公开 `review draft` 使用真实验证器的 verified/proposal_verified 合同；公开 draft → show → confirm → run 全链回归。
2. 配置真实技能目录时，发现先搜索全量真实元数据，不按 XLSX 适配器预过滤。模型显式选择返回候选；原生 skill_view 加载选中技能；非适配技能只发现、不得授权执行。无需技能的任务允许显式选择 none。执行仍限原有三个能力和已信任的固定适配器。
3. 冷技能在本轮独立 Hermes HOME 内真实归档，按需复用 Hermes restore_skill 恢复、原生 skill_view 加载，记录 canonical ID 与真实内容摘要。日常 Hermes 不归档、不恢复、不写历史。
4. 仅导入调用者显式提供的来源附件；原文不改写、不混入完整聊天。复用 ContextStore 的 session/hash、字段白名单、冲突、恢复和重验。要求行可引用已核验来源；确认与执行重新验证来源与技能绑定。来源缺业务决定仍阻断，不猜测。
5. 原有不带技能/来源的轻量路径兼容；自然语言用户不写任务 JSON。确认仍由可信用户/宿主执行，不向模型开放。

## 最小接口
- CLI draft 增 `--context-sources FILE`，数组格式沿用既有宿主 sources {source,event_id,payload,facts}，明确选择文件授予本次导入权限；暂不跨 session 自动检索。
- 父层将 source bundle 导入当前实际 native session，给模型仅相关事实与显式引用；draft requirements 可选 source_ref 引用附件，原文引用保持原规则。
- review 只在配置 catalog 时走 discover → select → native skill_view（选 none 跳过）→ propose → terminal。阶段间只传当前原文、候选元数据、已选技能内容/摘要和必要来源事实；不转发历史。
- 技能选择记录由父层产生，绑定 snapshot/skill/content/helper 摘要，进入不可变提案；确认前重验。无需技能与 adapter 不匹配必须明确拒绝。

## 有限验收与停止规则
- 一对 pilot 用冷 XLSX 与授权来源组合验证新增链路，修复后冻结正式协议。
- 正式四对任务：完整自然语言 CSV；真实冷 XLSX 技能选择及原 helper 调用；授权来源恢复业务键；来源仍缺业务键而拒绝。
- 两臂同模型、原文、来源供给、技能内容、业务约束和时间/调用上限。原生保留原生工具，不要求使用 RPE；RPE 从公开 draft 入口起跑。
- 评分按业务语义、实际产物、输入保护、真实调用和持久追溯；不强求未要求的冗余 flag。模拟审阅明确标记，不冒充真人。
- 成本报告全部逻辑 API、usage 已知量与缺失量、墙钟和前置工作；开发调用另列。失败/不确定必须保留，正式不重跑调参、不改旧版分数。
- 源码回归、打包独立安装验证与真实模型对照分开报告。净收益由结果决定，不预设成立。

## 清理
所有 venv、Hermes HOME、数据库、模型历史、临时产物置于独占 owned root；保留脱敏证据、源码、测试、报告和本地包。只清理登记的目录和进程；日常配置及既有三个仓库、历史报告以基线核对，遇外部漂移只记录，不覆盖。
