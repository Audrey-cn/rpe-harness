# RPE 1.9 干净入口、要求追溯与确定性执行

用户已批准按上一轮无记忆节点方案细化 todo 并以目标模式执行。范围保持现有三个能力：tabular.deduplicate、json.normalize、xlsx.inspect。Hermes 负责原生模型/工具生命周期与已有学习机制，RPE 负责来源、授权、确定性执行和独立验收；不增加分类器训练、常驻服务、通用语义保证或新飞轮。

## 可证明的边界

新增 clean 模式，保留1.8 address/strict/skills兼容。理解API请求必须由可信父进程保存的完整当前原文与固定目录/说明重建，不采用宿主messages历史、profile、工具结果或模型改写后的原文。实际llm_execution再次核对消息摘要/字节。错误纠正也只接收本任务有界错误，不附历史。节点隔离是消息/工具/状态授权隔离，执行继续使用既有独立worker和路径绑定；不宣称每个节点都是OS隔离进程。

机器可完整验收的来源 v1 是严格JSON根对象 {capability,constraints,execution}；不得含goal/note、重复键、额外字段、非有限值或尾随文本。每个显式要求生成确定性的JSON pointer、原值摘要、原文SHA和验收字段；空constraints也登记。模型必须与整份来源逐项相符，不能用goal吞掉要求或偷偷补猜字段。goal由可信代码固定生成。任意自由文字只可形成提案，终态needs_context/structured_current_request，不自动执行。这是有意保守的有限能力，不声称解决任意自然语言语义漏项。

新requirements.py提供source_document(raw,session_id,source_ref)、interpret_source_intent及SourceStateStore。ledger独立持久，与来源全文、session、原文SHA、要求摘要、既有MinimalStateStore状态关联；resolve重读复算，检测篡改、错来源/跨会话、目录撤权和输入变化。原1.8状态schema不变。公开CLI支持从严格来源prepare/show（零模型，准备阶段）；执行复用现有入口，不另造本地授权机制。Hermes clean仍真实调用一次理解工具以验收干净入口，然后由父进程执行，不让第二个模型复述state_id。自由文字拒绝也须可追溯原文。

## 执行与收据

ready后自动调度既有broker、BoundExecution、固定CLI、atomic publish和独立oracle。控制器调度使用独立类型收据，关联真实rpe_understand调用及state/ledger，不伪造rpe_task的模型tool_call_id或原生post_tool_call。不放宽原/task原生准入。单次声明/持久终态防重放，重启后不能再发布第二产物。新gate分别检查真实理解API/工具链、完整要求覆盖、控制器执行收据和业务oracle；controller execution与native tool invocation在报告中分列。

## 对照与验收

先无模型RED/GREEN验证来源漏项/冲突/未知约束/源篡改、A-B-A、并发、跨session/state、实际SDK工具加载和middleware/dispatch、真实API投影中无历史标记，完整旧回归与安装wheel验收。

最多1对pilot + 6对formal（14个实际Hermes会话）。formal在代码/依赖/模型/输入/评分冻结后才运行，不追加repair或重评失败。四个严格来源生产任务(CSV、TAB、JSON、XLSX)，两个来源边界probe(缺字段、自由文字含额外要求)。两臂收到完全相同的完整原文/文件/依赖/技能；严格JSON是公开用户输入，标准答案只在控制器。原生保留tool_search，clean固定工具政策；只能比较整体策略，不能归因单一模块或推广自由文字。全部pilot/错误/失败/usage缺失均计入总账，token不是实际账单。纯结构化CLI零模型另列，不混入真实Hermes成本。

清理前保留公开夹具与独立复验过的产物、脱敏收据证据、版本/成本/运行结论；离线复验可证明产物与公开要求一致，运行身份链是运行时核验记录，不把hash当独立第三方认证。只移除本轮owned-root/登记进程；日常状态漂移不盲目回滚。保留既有报告与旧仓，构建1.9 wheel、安装验收、本地发布分支与版本，归档工作树，不推送。
