# RPE 1.4 Implementation Plan / Todo

> Agentic workers: use superpowers:subagent-driven-development or executing-plans; each deliverable follows RED/GREEN and independent review.

**Goal:** JSON契约、诚实Registry发布前验收和跨任务复用构成一个可安装的本地1.4版本。
**Architecture:** 一个运行时、明确契约分派、独立产物验收和单一SQLite活动指针；旧资产继续默认未验证。
**Tech Stack:** Python>=3.10；标准库；openpyxl>=3.1.5,<3.2。
**Spec:** ../specs/2026-10-14-rpe-v14-design.md

## Global Constraints

- 不引入分类器、旧运行时或新的运行依赖。
- JSON只改变字符串外空白；预算固定1MiB输入/16MiB输出/64深度/100000token/256数字token。
- 样式pretty|minify必填；JSON候选不能借用CSV证书自动激活。
- Registry发布包验证不激活，不扩大信任根；缺依赖/环境失败关闭。
- 本轮测试资源仅owned-root，旧仓/日常服务保持治理边界，最终清理。

## Review Focus

1. pretty/minify身份混淆或tabular字段夹带：拒绝并保持不同receipt/plan hash。
2. 数值/字符串词法变化、bool/int相等陷阱：非空白token独立核对。
3. 绑定源路径的超限读取、深层结构或格式错样式：预算内拒绝且无输出覆盖。
4. catalog/audit/package来源串用、撤销、过时修订和缺验收环境：失败，不能成功skip。
5. 重启/坏候选/休眠查找被误算学习收益：只根据真实调用和产物记录报告。
