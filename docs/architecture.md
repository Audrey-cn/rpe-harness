# 架构设计

## 核心问题

Hermes Agent 的 Memory 和 Skills 持续增长后：
- 技能检索、任务路由成本线性增长
- 冷门技能长期不被调用 → 丢失/冷却 → 不可达
- 每次任务都需要 LLM 浏览完整技能库

## 解决方案：分层能力寻址

```
用户任务 / 环境事件
        ↓
┌─────────────────────────┐
│    能力寻址层            │
│  意图识别 · 条件过滤     │
│  候选排序 · 因果关联     │
│  失败降级               │
└────────┬────────────────┘
         ↓
┌────────┴────────┬──────────────┐
│   技能索引       │  因果关系图   │  历史经验
└────────┬────────┴──────┬───────┘
         ↓               ↓
┌─────────────────────────┐
│ 选择本地技能 / 请求模型  │
└────────┬────────────────┘
         ↓
┌─────────────────────────┐
│   执行验证与经验回写     │
└─────────────────────────┘
```

## MCSI（最小因果状态接口）

节点间传递的不是完整上下文，而是最小充分状态：

```json
{
  "task_type": "spreadsheet.deduplicate",
  "input_format": "xlsx",
  "constraints": ["preserve_formulas", "preserve_original"],
  "required_capability": "spreadsheet_cleaning",
  "source_ref": "evt-12345"
}
```

### 设计原则

1. **状态充分性优先于上下文完整性**
2. 每个状态可追溯到原始事件（source_ref）
3. 下游置信度不足时可请求补充上下文

## 分层路由

| 层级 | 工作方式 | 成本 | 目标 |
|------|---------|------|------|
| L0 | 确定性路由 | ~0 | 不调 LLM |
| L1 | 能力分类 | 低 | 缩小搜索范围 |
| L2 | 关系与因果检索 | 中 | 找可执行技能 |
| L3 | 开放式推理 | 高 | 探索新能力 |

## 程序性能力沉淀

| 层级 | 固化内容 | LLM 依赖 |
|------|---------|---------|
| L1 | 经验规则、提示词、检查清单 | 高 |
| L2 | 参数化脚本、API 工作流 | 低 |
| L3 | 确定性本地程序、状态机 | 近零 |

## 能力可达性

技能可以退出活跃记忆，但不能失去可发现性：
- **活跃技能**：高频使用、快速路由入口
- **休眠技能**：不占常驻上下文，保留索引和触发条件
- **待验证技能**：过期/失败率升高，调用前需重新测试
