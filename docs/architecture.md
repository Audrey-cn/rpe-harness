# 架构设计（1.3 融合）

1.3 按 [融合设计](fusion.md) 选择性吸收阿卡夏资产封装、内容寻址、签名与本地目录获取。RPE 是唯一执行/验收/反馈/激活权威；旧 Registry 是资源仓，旧 Protocol 是历史参考。新资产层不引入旧运行时、第二套 GeneLedger 或额外运行依赖。

## 核心问题

Hermes Agent 的 Memory 和 Skills 持续增长后：
- 技能检索、任务路由成本线性增长
- 冷门技能长期不被调用 → 丢失/冷却 → 不可达
- 每次任务都需要 LLM 浏览完整技能库

## 1.2 执行基础与分层能力寻址

RPE-Harness 是独立的能力与执行层。模型负责理解和探索，Harness 保存契约、执行经验、验证证据和版本；Hermes 是第一个宿主。原始对话强调模型可替换、能力可积累、冷门技能仍可发现，以及最小充分状态。助手在旧对话中的研究设想不等同于已经实现的能力。

可执行任务先声明能力。1.2 的 schema v2 直接寻址注册执行器，任务类型分类、关键词相似度和外部技能排名不能授予执行权限；路由仍可作为推荐接口。冻结执行计划绑定输入 hash、路径、关键列、选项、契约和可信执行/验证修订，独立验证器重新读取源文件与产物。候选版本和代码 hash 另行绑定执行证据。

```
用户任务 / 环境事件
        ↓
┌─────────────────────────┐
│    能力寻址层            │
│  意图识别 · 条件过滤     │
│  候选排序 · 因果关联     │
│  失败降级               │
└────────┬────────────────┘
         ↓
┌────────┴────────┬──────────────┐
│   技能索引       │  因果关系图   │  历史经验
└────────┬────────┴──────┬───────┘
         ↓               ↓
┌─────────────────────────┐
│ 选择本地技能 / 请求模型  │
└────────┬────────────────┘
         ↓
┌─────────────────────────┐
│   执行验证与经验回写     │
└─────────────────────────┘
```

## MCSI（最小因果状态接口）

节点间传递的不是完整上下文，而是最小充分状态：

```json
{
  "task_type": "data.processing",
  "input_format": "xlsx",
  "constraints": ["preserve_formulas", "preserve_original"],
  "required_capability": "tabular.deduplicate",
  "source_ref": "evt-12345"
}
```

### 设计原则

1. **状态充分性优先于上下文完整性**
2. 每个状态可追溯到原始事件（source_ref）
3. 下游置信度不足时可请求补充上下文

当前正式执行协议使用 `schema_version=2`、`event_id`、`capability="tabular.deduplicate"`、`goal`、`constraints` 和 `execution`，格式由实际文件探测。V1 保留兼容校验；历史事件按持久记录重放。MCSI 是推荐和交流状态，不能替代文件执行契约。

## 分层路由

| 层级 | 工作方式 | 成本 | 目标 |
|------|---------|------|------|
| L0 | 确定性路由 | ~0 | 不调 LLM |
| L1 | 能力分类 | 低 | 缩小搜索范围 |
| L2 | 关系与因果检索 | 中 | 找可执行技能 |
| L3 | 开放式推理 | 高 | 探索新能力 |

这些是寻址层次，不是升级验收标准。因果图仍需干预、消融和独立真值验证，不能从合成路由得分宣称收益。

## 程序性能力沉淀

| 层级 | 固化内容 | LLM 依赖 |
|------|---------|---------|
| L1 | 经验规则、提示词、检查清单 | 高 |
| L2 | 参数化脚本、API 工作流 | 低 |
| L3 | 确定性本地程序、状态机 | 近零 |

## 能力可达性

技能可以退出活跃记忆，但不能失去可发现性：
- **活跃技能**：高频使用、快速路由入口
- **休眠技能**：不占常驻上下文，保留索引和触发条件
- **待验证技能**：过期/失败率升高，调用前需重新测试

## 自学习、自净化、自纠错

1.2 复用 [Hermes Curator](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator) 的程序性记忆、生命周期、原子变更和回滚思路，以及 [Reflexion](https://arxiv.org/abs/2303.11366) 的环境反馈和 [GEPA](https://arxiv.org/abs/2507.19457) 的候选与评估分离。产品不引入完整训练框架，也不以文本相似度替代执行验收。

无人值守周期收集持久验证反馈，合并重复经验并生成结构化提案。提案可涉及整个 Harness；自动激活由证据和操作范围决定。已知 CSV 契约的配方和 Python 执行器候选可经过独立留出反例、资源/文件权限限制和版本校验后自动激活。每次生产执行仍须通过原计划的独立验证；失效版本进入隔离并回到内置执行器。经验休眠后仍保留查找键，历史证据不随净化被删除。

核心代码、新能力和验证器升级也保存为提案。它们需要适合该变更的外部可信验收集和发布策略，现有去重样例不能证明任意升级正确。架构不永久排除这些升级，也不允许候选自己降低验收标准。

候选进程的内存监督由可信父进程通过标准库 ctypes/libproc 读取 Darwin RSS，软阈值为 128 MiB、轮询间隔 20ms。读取失败不按低内存放行；完整响应才有效，仅已消失的目标返回空值。该软监督不保证瞬时分配峰值。文件、网络、fork、CPU 和输出限制，以及每次生产的独立验收仍分别保留，RSS 不能替代这些边界。

## 宿主入口、恢复与证据

Hermes 严格入口使用官方 middleware：关闭延迟发现、直接暴露任务工具，指定 `tool_choice`，获得匹配的持久结果后才允许生成总结。最终验收核对真实调用 ID、收据、运行记录和重新读取的产物。固定请求锚可以检查参数是否忠于用户契约；自然语言入口仍需业务验收来发现意图抽取误差。

隔离启动器把执行权放在宿主沙箱之外：可信父进程按次建立随机凭据认证的本地回环入口，Hermes 插件只提交业务请求与已持久保存的 receipt；入口再核对工作区、调用/会话身份、契约和当前输入 hash，启动固定 Harness CLI。CLI 冻结计划，选择已有执行器或已验证候选，完成独立验收和发布。入口不提供任意脚本执行权限，严格模式还核对实际 API 的指定工具策略及同轮终态。

```text
模型 / Hermes（宿主沙箱保留）
        ↓ 业务参数 + 调用身份 + 持久 receipt
启动器父进程中的临时认证回环入口
        ↓ 固定 Harness CLI（位于宿主沙箱外）
冻结计划 → 执行器 / 单层沙箱候选 → 独立 verifier → 发布
```

这一边界使独立 Harness 的执行状态和验收职责不依赖宿主内部能否再次施加 macOS 沙箱。候选权限保持原限制；真实模型的严格准入和最终 gate 也不因外部执行而省略。入口和执行子进程随会话创建、关闭，保留超时、进程组及已登记后代清理证据；没有长期安装服务或自动创建定时任务。手动插件的直接子进程兼容路径与启动器的外部执行模式不同，具体配置见 [Hermes 接入说明](../integrations/hermes/README.md)。

1.3 外部入口将源文件与输出目录描述符传给固定 CLI，源读取使用绑定的文件，暂存位于可信数据库父目录，发布使用输出目录描述符。替换路径后拒绝，最后检查后的竞态也不会沿新链接向外发布。信任边界包含父进程、SQLite/其父目录及候选 owned-root；不声称能隔离任意同 UID 对已绑定目录对象的移动。暂存/输出需同一文件系统。不支持绑定的平台拒绝。发布硬链接后检测到替换，原绑定目录仍可能保留已验证文件，运行记录保留失败/未知发布结果，不自动恢复。1.2 [旧缺口证据](../reports/v1.2.0/evidence/review/external-executor/README.md) 保留为历史。

已完成任务幂等返回原结果。恢复只允许原进程停止、源 hash 未变、输出不存在且未进入发布的失败尝试；保留尝试关联并限制次数。发布开始后的未知状态不能静默改成成功或覆盖文件。

固定样例证明当前契约范围，重复原生对照衡量特定宿主、模型和任务集的可靠性与成本。独立新会话重复不等于多轮会话记忆实验；模型总结、外部 usage 和合成路由分数均不是学习收益证明。详细边界见 [1.2 设计](superpowers/specs/2026-10-14-rpe-v12-design.md)。
