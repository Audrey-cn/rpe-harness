据此，升级提案范围覆盖整个 Harness。1.2 已允许客观验收后的既有契约执行器代码自动激活。新能力、核心执行器和验证器也能形成提案；它们需要相应的外部可信验收集和发布策略。升级范围随证据扩展，不以“配置可以自动改、代码永远只能提案”作为架构边界。

历史中的几何空间、因果图、最小因果状态充分性仍是待验证假设。现有路由微基准和关键词命中不能证明这些机制有收益。

## 已交付的执行架构

```mermaid
flowchart LR
    A[用户任务 / 宿主事件] --> B[注册能力契约]
    B --> C[冻结执行计划与输入 hash]
    C --> D[内置或已验收的候选执行器]
    D --> E[独立验证原计划与暂存产物]
    E --> F[无覆盖发布与持久收据]
    F --> G[反馈 / 紧凑经验 / 索引]
    G --> H[全架构升级提案]
    H --> I[独立验收与资源约束]
    I --> J[版本激活 / 回滚 / 隔离]
    J --> D
```

1. **执行去分类依赖。** V2 请求直接声明 `tabular.deduplicate`，包含目标、约束和执行参数；实际探测 CSV/XLSX。V1 保留兼容。错误分类、技能排名、图和元数据异常不能改变已注册执行器的授权。
2. **计划约束生产与验收。** 原始请求在准入前深快照，冻结计划绑定源文件 hash、输入/输出路径、关键列、选项及契约、执行器、验证器修订。产物必须重新按原计划验证；生产器改 key、sheet、输入或输出不能自行证明成功。
3. **真实 Hermes 入口。** 严格模式关闭延迟工具发现，直接暴露 `rpe_task`；官方 middleware 在有效持久终态前指定该工具，并关闭并行工具调用，终态后请求 `none`。业务参数在内部转换成 V2。固定 `--request` 可锚定用户契约；未固定的自然语言抽取仍需业务真值检查。
4. **最终验证门。** 实际 API/turn/tool IDs、模型响应中的调用、工具收据、持久运行、计划和重新读取的产物必须相符。宿主 `completed` 或文字总结不代表 Harness 已验证。观测缺失、调用策略被忽略、没有有效收据均返回未验证。
5. **可恢复的持久执行。** 停止后且发布意图前的失败，只能在原输入和执行修订未变、输出不存在时恢复，后继尝试持久关联且幂等。默认总尝试预算 3。发布后的未知结果保留证据并拒绝自动重试。

隔离宿主的实际候选验证暴露了 macOS 的嵌套沙箱限制：即使两层均 allow-default，第二次 sandbox_apply 仍返回 exit 71。最终版本保留 Hermes 沙箱，改由父进程按次启动临时鉴权回环入口，核对工作区、工具收据、五类原生 ID、实际 API 策略及契约/输入 hash，然后在外部启动固定 Harness CLI；候选获得自己的单层沙箱。关闭时停止拥有的进程组和已登记后代，主动关闭连接、限制 worker 等待，并删除绑定到工作区的私有临时目录。清理观测不足会让最终验收失败。[失败快照](evidence/pre-external-executor/snapshot.json)、[源码与最终包身份](evidence/frozen-source-manifest.json)。

**已知未修复缺口：并发目录替换。** 当前父侧固定 CLI 没有与 Hermes 宿主同等的工作区文件沙箱，信任父进程、SQLite 及运行期间稳定的工作目录。额外独立探针在服务端验证后、CLI 启动前替换目录，实际返回 HTTP 200 / succeeded，并在声明工作区外生成产物。探针没有模型调用或日常环境写入；其 broker hash 与36项 GREEN 的快照相同。入口认证、冻结 hash 与事后验收未原子绑定目录对象，同 UID 外部并发目录 mutation 仍未硬隔离。36项通过只支持原检查范围，不能把此 finding 写成修复完成或整体安全审阅通过。[独立证据与检查范围](evidence/review/external-executor/README.md)、[目录替换 RED](evidence/review/external-executor/workspace-swap/evidence.json)。

当前产品能力仍是明确关键列、保留首次记录的 CSV/XLSX 去重。表格源保留、非关键列、顺序、类型区分、支持的公式和样式由实际文件验收。openpyxl 不计算公式，因此不能据此证明 Excel 计算值。其他技能仍为推荐索引，不能自动执行任意 SKILL.md。

## 轻量飞轮与自动升级

借鉴了 Hermes 的程序性记忆与生命周期，采用持久反馈、紧凑经验、原子变更和回滚；参考 Reflexion 的环境反馈，以及 GEPA 的候选生成与独立评估分离。产品未引入完整训练框架，运行依赖仍只有 openpyxl 3.1.x。来源：[Hermes Curator](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator)、[Hermes Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)、[Reflexion](https://arxiv.org/abs/2303.11366)、[GEPA](https://arxiv.org/abs/2507.19457)。

Hermes 官方 self-evolution 仓库的固定快照 `0a929e3aa20e15cf04dc7c28492a7d41a5139125` 中，已检查的 fitness 是词集重叠，不能代替真实工具和产物验收。此版本只参考机制，未复制其框架代码或引入额外依赖。[固定源码快照](https://github.com/NousResearch/hermes-agent-self-evolution/tree/0a929e3aa20e15cf04dc7c28492a7d41a5139125)

| 机制 | 实际行为 | 证明边界 |
| --- | --- | --- |
| 自学习 | 只收集持久、已发布、计划绑定且仍可复查的成功反馈；形成可索引经验及证据提案 | 没有权重训练；尚未证明长期迁移或自然发现新能力 |
| 自净化 | 去重经验，复查失效证据，休眠/隔离保留索引、来源和版本记录 | 不将低频等同于无价值，不删除用户历史来“净化” |
| 自纠错 | 受限重试、独立产物检查、坏候选隔离、同计划回退和版本回滚 | 发布后结果未知不会静默改成成功 |
| 无人值守提案 | `evolution cycle` 在没有模型时也生成全架构结构化提案，可注入 Agent 提案生成器 | 不自动创建本机定时任务；需要由现有调度器调用 |
| 基础自动升级 | 既有 CSV 契约的配方和 Python 执行器通过验收后自动激活 | 任意核心或验证器改写需要相应可信外部验收 |

代码候选 ABI 为 `prepare(plan, staging_path) -> None`，只能生成暂存文件，发布仍由原执行层完成。API 强制非空、可复查的已验证运行证据；本轮演示绑定两条 CSV 反馈。验收包含 3 个开发样例（代码中标记为 train，未进行模型训练）和 10 个留出样例；内容 hash、完整证书、实际重放及事务内二次检查/CAS共同约束激活。生产执行继续使用原计划的独立验证器。

macOS 候选子进程沙箱拒绝网络、派生进程、外部写入及读取实际 Harness 验收包，限制 CPU、文件体积和打开文件数。内存通过标准库 ctypes 调用本机 libproc 观测，权限或不完整观测明确失败；限制为 128 MiB RSS、20 ms 轮询的软监督；本机的 AS/DATA/RSS 硬限制不受支持，瞬时峰值没有硬上限保证。SQLite 与可信父进程是信任根；不能把公开 hash 当作对任意数据库控制者的认证。

### 本机 CLI 生成执行器的真实验证

本机 Codex CLI 在临时、只读、无历史持久化的会话中，以契约和 ABI 生成了 1,766 字节 CSV 执行器，32.812 秒、退出码 0。代码 hash：`ed3882aee3ce8e036071effbf11da6df46e276cb75c3055056c483c5f233698e`。候选生成未提供留出夹具或验收器。

安装包实际执行验证了：13 个验收夹具通过 → 自动激活 → 后续任务确实使用该版本和代码 hash → 回滚后任务使用内置版本 → 再次激活并故意损坏 owned 中的版本 → 下次任务隔离损坏版本并按原计划回退内置版本。这一周期获得 4 条验证反馈、产生 10 个提案。

这些反馈来自合成文件夹具通过安装包 CLI 的真实执行；不能描述成真实用户流量或 Hermes 反馈。此实验验证升级机制可用，未证明候选执行器提升性能。证据：[代码生成](evidence/generation-codex-2-success.json)、[升级与实际调用](evidence/generated-executor-evolution.json)、[候选源码](artifacts/generated-csv-executor.py)。

全部生成尝试保留：Hermes 两次超时未产生候选；Codex 第一次受 OS 启动限制未进入模型；第二次成功。前两次 usage 未完整观测，不能计作零费用。Codex 用量与 Hermes 对照模型不同，不合并进行节省计算。
