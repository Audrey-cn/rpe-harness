# RPE-Harness 1.15.3：Hermes 兼容与复验

上一轮在真实模型启动前就被拦住。本机新版 Hermes 把 `stream-json` 聊天交给网关，旧隔离入口的预算参数不再适用；冷技能的来源回执也换了格式；本机 XLSX 助手改了一条注释，旧指纹不再匹配。本轮逐项修复这些阻塞。

- 对新版 Hermes，在原有独立进程内使用 Hermes 自己的 Python Agent 和事件输出器。保留明确的模型、工具集和预算，旧入口继续走原有 CLI。这里的原生对照指同一 Hermes 执行器及原生工具，在同样的受控测试环境运行，不等同于用户平时开启记忆的默认会话。
- 冷技能仍须恢复后读取实际文件。新版必须同时回报正确的相对路径和绝对目录；旧版如果给出 `_source_path`，仍须完全匹配。两种格式都要通过文件所有权边界和内容校验，链接或冲突证据会被拒绝。
- XLSX 增加一个经审查的本机字节版本，原文件与旧版的语法树一致，只差 Ruff 注释。仍按 `SKILL.md` 和助手文件的成对指纹识别，任何未经登记的更改都会被拒绝；已批准文件换成另一组已知字节也需重新授权。

独立审查还发现了两项隔离问题。原生沙箱只增加一个依赖 Python 标准库的来源校验模块；已有工作流、门禁和路径绑定代码仍不可读。启动器以一次性管道交接密钥；在本机新版的实际沙箱测试中，服务端替身收到了正确的授权头，终端却无法从 `.env`、环境或进程参数取得假密钥。旧版 CLI 分支用替身验证了密钥交接和子进程环境清理，没有在另一份旧版 Hermes 安装上复验。

超时用例原先可能在测试程序拉起子进程前就超时，没测到要检查的进程组。独立探针的五次启动耗时约 496–557 毫秒。修后的夹具等子进程确认就绪后才进入原有 1 秒计时，并检查该子进程确实退出。两个测试配置均通过；生产超时和清理策略未改。原始失败、启动探针和修后证据分别留存。

隔离试验只登记一个新 XLSX 对照样本的实际运行名额：两边各一次起草，原生通过起草、来源和模拟审阅门禁后才允许一次执行。模拟审阅不代表实际用户确认；工具循环可能带来多笔 API 请求，账本记录已观测用量，未核实服务商收费。单个样本不能证明普遍的质量、成本或无人值守收益。

## 真实对照：两个结果一致，RPE 少用模型

同一小米 `mimo-v2.6-pro` 模型处理此前未跑过的「验货」工作表。模式和工作表来自显式附件。输出须保留前导零、原行序及数字和布尔类型。RPE 经公开入口起草和模拟确认后，由既有控制器执行；Hermes 原生经自己的工具执行。两侧均恢复真实冷技能，生成的 JSON **逐字节相同**，原输入都没变，均通过独立业务验收。原生还记录了已验签的 Darwin helper 退出收据，退出码为 0，记录的 stdout 与最终文件相同；该收据不证明唯一写入者。

| 路径 | 模型请求 | 总 token | 其中缓存读取 token | 实际产物 |
|---|---:|---:|---:|---|
| RPE：起草后确定性执行 | 4 | 11,755 | 0 | 通过 |
| Hermes 原生：起草与执行 | 6 | 68,327 | 42,496 | 通过 |

这个样本 RPE 的总 token 少 **82.8%**。10 笔请求都有用量回执，响应模型均与请求模型相符；其中原生起草 49,282 token、执行 19,045 token。缓存计费和账单未核实，不能把 token 差额当作费用差额。两侧的草稿和执行都没有重放。原生与 RPE 的产物和账本已由安装包中的离线验证器复算；运行收据仍属于当时记录的观测。正式配置中其余两个任务未跑，因此这对样本可比较，完整比较依然 `comparison_ready=false`。见[模型结果](validation/model-result.json)、[用量账本](validation/model-evidence/cost-phases.json)与[离线复算](validation/model-offline-verification.json)。

## 安装包与环境

本机 macOS 27.0.1；项目测试 Python 3.12.14，Hermes `b200f5bc60` 的运行时为 Python 3.14.7。隔离项目 venv 不继承系统包，子进程使用绝对模块路径。源码、wheel 和从 wheel 安装后的 95 个 Python 文件字节完全一致；当前 Hermes 依赖和 RPE 源码的记录指纹在在线对照前后也相同。

- 安装包最后一次验证 **300 通过、2 跳过**。首轮包验证保留 **299 通过、1 失败、2 跳过**，失败为冷技能的 `loaded` 收据。首轮启动与测试夹具修改时间重叠，失败栈行号不对应最终夹具。同一 wheel 上，单项复查与随后完整的 302 项包检查都通过对应收据用例；首轮失败不重写。
- 源码全量 **2,215 项通过、7 项跳过、3 项子测试通过**。全量测试前后、真实对照前后，记录的 RPE 源码、本机 Hermes 源码和依赖、Python 解释器及配置指纹一致。
- 显式指定本机 Hermes 后，默认套件中需要该设置的 5 项 SDK/原生插件用例单独通过。

## 清理与交付范围

主验证的专属目录已移除：32,779 个普通文件、1,416 个符号链接，包括测试环境、缓存、历史和临时执行状态。密钥副本先行删除，保留的在线证据未发现密钥。删除前后分别按进程命令和工作目录核对，均无残留；并行子任务也分别清理了自己的目录。

日常 Hermes 配置和授权文件、Claude 配置未变。日常 Hermes `state.db` 和 13 个技能目录路径在时间窗内有变化，来源未确定，没有覆盖、回滚或清理这些日常内容。用稳定的 DB/WAL 副本查询本轮 3 个会话，在日常 `sessions` 和 `messages` 中均无匹配。两个旧 Progenitor 仓库的 HEAD 和工作区状态未变。见[清理回执](validation/cleanup.json)和[会话检查](validation/daily-session-check.json)。

1.15.3 是本地兼容维护版。源码和安装包检查通过，已完成一对真实任务的验收。剩余两个对照样本、服务商账单及长期无人值守仍没有本轮证据。完整回归、首轮失败和最终结果均保留在 [`validation/`](validation/)；[可安装 wheel](release/rpe_harness-1.15.3-py3-none-any.whl)随仓库保存。
