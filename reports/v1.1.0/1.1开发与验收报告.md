# RPE-Harness 1.1 开发与验收报告

验收日期：2026-10-13 至 2026-10-14。产品边界仍是独立 Harness，Hermes 是第一个真实宿主。1.1 新增本机 Hermes 事件观察、原生 `rpe_task` 工具、隔离启动器和成对实验；没有扩展为通用 Agent 执行平台。

## 交付内容

| 能力 | 1.1 的实现与验证边界 |
|---|---|
| 真实宿主事件 | 通过 Hermes 原生插件 hook 同步落盘 session、LLM、API、tool 元数据；将实际 session/turn/API/tool_call ID 与 Harness run 关联。原生事件没有 event ID 时保持 null，另存本系统 ingest ID。 |
| 真实工具执行 | Hermes 注册并调用 `rpe_task`；先落 receipt，再启动独立兼容 Python 执行 1.0 的持久运行和独立产物验证；回传精简 JSON。 |
| 故障可见 | Hermes 本身可能吞掉 hook 异常；观察器另写私有、不含正文的故障标记，启动器据此判定此次观测不完整，不把它算作成功。 |
| 隔离调用 | 每次使用专属 home、runtime、缓存、工作区和数据库；只复制现有 Xiaomi API key 与套餐 URL，禁用日常 memory、外部插件、MCP 和后台辅助调用；不复制 OAuth 刷新状态。 |
| 使用入口 | `rpe-harness hermes run --workspace … --prompt-file … --db …`；宿主退出成功和 Harness 产物验收成功分别报告；未验证任务返回非零退出码。 |
| 安装包 | Python wheel 1.1.0，可安装后使用；Hermes 原生插件模板及独立对照 API 一并提供。 |

本机验收对象是 Hermes 0.21.7+279，源码 HEAD `63d0b94120027d487c9a5235b9ec64b696af1b26`。启动器直接使用本机已经安装的 Hermes Python 依赖环境，禁止自动修复/下载依赖。当前隔离启动器只支持 macOS 与现有 Xiaomi API-key 配置；直接使用插件的 provider 边界由 Hermes 自身决定。

## 正式原生对照

正式结果以 [hermes-native-comparison.json](evidence/hermes-native-comparison.json) 为准。六个任务各跑原生、集成两个新会话，顺序交替；同一对使用字节完全相同的输入、提示和模型设置。原生臂使用 Hermes 文件/终端工具自行实现处理，不能读取 Harness 执行器或验收答案；集成臂另外提供专用任务工具。双方均启用同一个事件观察器。

两边的同一提示明确使用 `"$RPE_HARNESS_PYTHON"`，解释器已具备 csv/openpyxl。先前默认终端 Python 缺 openpyxl，导致安装尝试与超时，因此该批只作为 [依赖环境调试记录](evidence/dependency-baseline-trials.json)。正式会话不把依赖安装时间混入能力对比。验收器曾将这个解释器变量及其打印标签误判为实现引用；修正只豁免完整、大小写准确的变量名，并保持真实实现导入和变量后缀拒绝、原始工具输入哈希不变。模型行为和沙箱不变；正式会话在结束后用修正验收器统一重验，保留修正前的判断供复核。

四个成功任务覆盖中文和前导零 CSV、含引号/换行的复合键 CSV、XLSX 数值与文本键的区别，以及原坐标公式、样式、注释、超链接、隐藏工作表和列宽。两个拒绝任务覆盖 JSON 不支持、保留公式引用待清空的重复行。验收器在模型外重新读取实际文件并检查手工真值、原输入哈希、正确拒绝理由和无输出；集成臂还要求真实 `rpe_task` 调用、原生 post-tool 事件到 durable run 的关联，以及成功运行的 verification/artifact 证明。

正式 **12 次均已执行并验收**；10 个宿主会话正常结束，2 个原生 XLSX 会话超时。严格验收原生 **4/6**，可选工具的集成臂 **4/6**。两边六组的提示哈希、输入哈希、请求设置及实际响应模型一致；实际响应模型为 `mimo-v2.6-pro`。全部会话的进程清理记录为完整、无剩余后代。

最终安装 wheel 的明确工具调用验收 **6/6 通过**：四项真实文件及独立验证、两项正确拒绝，均关联原生工具调用与 durable run，见 [installed-hermes-e2e.json](evidence/installed-hermes-e2e.json)。两场真实会话共八次 `rpe_task` 调用：首场的两个 CSV 验收请求误带 XLSX 专用 `preserve_formulas`，被正确拒绝，修正后仅补跑两项 CSV；原始错误请求和修正请求都保留。这是验收输入修正，不是跳过产品失败。该实验与可选工具的配对实验分开，不混入上表时间或 token。

正式验收修订的输入/提示/工具哈希保持不变，见 [acceptance-revalidation.json](evidence/acceptance-revalidation.json)，修订前结果分别保存在 `acceptance-before-variable-fix.json` 和 `acceptance-before-label-fix.json`。合成输入与实际产物保存在 `artifacts/validation-files/`、`artifacts/explicit-tool-files/`，供直接检查；这两处不保留聊天正文、临时脚本或凭据。

用量保留真实 provider usage 的字段存在性、缓存与 reasoning 口径。缺失数值为 null；原始 total 优先，只在输入和输出均已报告时才派生 total；reasoning 不重复加到 output 上。这里不推算套餐费用，也不把一次、六任务的小样本结果外推为通用 Agent 优势或因果图收益。

## 回归、安装与发现的修复

完整回归 **230 项通过，无跳过**，包括本机 Hermes 原生 loader/dispatcher 和真实沙箱测试。证据分别见 [pytest.log](evidence/pytest.log)、[pytest.xml](evidence/pytest.xml)、[installed-contract.json](evidence/installed-contract.json)。最新安装包在源码目录以外运行六项实际文件契约全部通过；openpyxl 来自本机只读 bundled runtime，网络依赖拉取不可用，因此不宣称完成完全独立的网络干净安装。

本轮真实验证修复了以下问题：

- 中文路径的 sandbox 字符串必须保留实际 Unicode，不能沿用 JSON 的 Unicode 转义。
- SQLite 的精确写权限必须同时覆盖已知 WAL/SHM/journal 和 lease；读取隔离目录时也要允许本次数据库侧文件。
- 标准 XLSX 注释使用 Note VML，过去被复杂 drawing 检查一并拒绝；现在只放行标准注释，仍拒绝图片、控件等其他 drawing。契约保留注释文本/作者，不保证批注框几何尺寸。
- 原生臂通过拆分字符串导入仍可能读到项目模块；现在由文件沙箱阻止读取执行器与答案，不只依赖提示/命令文本检查。
- hook 异常、未配对 API 请求及 SDK 默认零值会让观测看起来完整；现在用故障标记、请求/响应配对、字段来源校验报告未知和失败。
- 仅周期扫描可能漏掉父进程很快退出的子进程；现在在本次宿主内对直接 spawn 同步登记，再核对启动身份回收。macOS 沙箱无法执行 setuid ps，因此登记改用 libproc 系统接口；外部回收器仍使用独立 ps 身份复查。
- 损坏的 spawn journal 曾可能在 finally 内先抛异常、跳过停止宿主；现在保证先回收确切自有 host 和已知后代，再把读取/查询故障作为 stage/type 记录并阻止验收。故障探针与正常控制均通过，最终安装包真实会话也使用这一修复。

前期真实会话、观察器失败试验、子进程登记启动失败均单独保存摘要：[preliminary-comparison.json](evidence/preliminary-comparison.json)、[isolation-pilot-comparison.json](evidence/isolation-pilot-comparison.json)、[observer-failure-trials.json](evidence/observer-failure-trials.json)、[bootstrap-registry-trials.json](evidence/bootstrap-registry-trials.json)。前两份是同一批六个通过会话的重复检查点，计数只算一次；观察器失败试验有四个未完成验收的会话，登记启动失败有十二次启动、零模型请求。它们用于说明修复经过，不能作为最终版本的完整验收替代物。

## 本机影响与清理

本次全部临时开发环境、测试 home、原始会话、凭据副本、缓存和探针位于专属 `/tmp/rpe-v11-development-20261013/`。该目录已整体删除，回收 599,639,467 字节，移除两个本轮项目缓存目录，测试进程剩余 **0**。最终保留代码、wheel、脱敏元数据、合成验收文件与报告；清理结果见 [cleanup.json](evidence/cleanup.json)。

日常 Hermes 源码 HEAD/工作区、config.yaml 和 .env 与开始时一致。auth.json 与 state.db 在观察期间有变化，不能声称它们字节不变；只读核对发现日常库存在 cli/desktop/oneshot 活动，35 个已知试验 session ID 均不在日常库，测试 source/工作目录匹配数为 0。Nous 认证元数据在全部试验进程结束后仍更新，与日常独立活动相符，但本次没有归因到具体认证写入进程。没有回滚、删除或重写这两个日常文件，没有停掉日常网关或清空共享缓存。

进程回收依赖本次宿主的进程组、直接 spawn 登记、祖先追踪和启动身份复查；不将它描述为任意恶意 daemon 的完整隔离保证。实际沙箱探针验证了命令执行、登记和脱离进程组的 sleep 回收，以及无关控制进程不受影响；见 `evidence/sandbox-validation.json`。不会清空用户共享缓存或历史、改动日常认证配置、停掉日常网关。

独立终审已核对真实事件 ID、工具输入哈希、API/工具配对、最终 wheel 与安装字节、四项产物及两项拒绝、异常清理修复，未发现未关闭的 P1/P2；见 [independent-review.json](evidence/independent-review.json)。

## 下一步方向

1. **1.2 首先解决工具发现与调用门槛**：减少搜索/描述和无效请求，确保明确要求可验证执行时必须进入 Harness；未入工具的产物继续保持 unverified。1.1 的可用边界是明确指定 `rpe_task` 的已验收调用，自动工具选择仍不稳定。
2. **完善可靠性与适配面**：增加超时、断流、事件落盘失败、工具重试/重复提交、宿主崩溃的真实故障实验；扩展 provider 适配时保持认证状态隔离。逐项公开正确恢复、明确失败和未知观测的结果。
3. **扩大原生基线**：使用多次重复、更多真实文件和固定预算，记录请求模型与实际响应模型，分别比较成功率、延迟、请求数、缓存口径 token。先稳定可重复实验，再讨论收益。
4. **建立第二宿主与第二执行能力**：沿用明确状态协议、可验证产物和独立执行器，不把 Hermes 的工具目录当作 Harness 架构边界。
5. **因果图作为后续研究项**：只有在加入公平对照、消融、真实 ground truth 后才能宣称对寻址或恢复有额外收益；1.1 不对此作新结论。
