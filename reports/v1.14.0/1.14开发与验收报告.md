# 1.14 开发与验收报告

本轮已经补齐最终源码的真实模型入口证明和独立 CLI 审阅，但**新的受限请求配置尚未通过业务验收，不建议默认启用**。四组新任务的严格完整链结果，RPE 与原生均为 **0/4**。这不是“两个系统什么都不会”：原生冷表产物正确，缺业务键时两边都停止了执行；它说明参数、协议和证据边界仍会阻断真正可用的闭环。

## 本轮具体完成了什么

- 公开自然语言入口可用 `--request-budget PATH` 传入显式的隔离请求预算。业务原文、要求清单与确认边界保留。当前测试配置为两臂相同的 2400 输出上限、关闭 thinking、90秒 request/stale I/O 限额，外层180秒、8轮。
- 复用 Hermes 的请求 builder、streaming、原生工具事件与 post-tool end_turn。没有新增运行依赖或常驻服务。文件收据齐全后可正常结束，结束本身不等于通过业务验收。
- 非 XLSX 业务产物增加真实 before/after IO 与私有 HMAC 收据，避免只凭某种命令写法判断有没有执行。XLSX 继续要求原技能、原 helper、冻结解释器、实际内核退出和最终产物绑定。
- 修补 Claude Code 结构化审阅契约、短输出与隔离状态目录；一次两例预检成功。正式八例仍在180秒超时，不能把这称为限额问题已全部解决。stderr没有给出可证实的429或quota原因。
- 备用 Codex CLI 在28.23秒内完成同一八例盲审，一轮、退出码0，实际工具调用0。5/8 被评为理解忠实，所有产物正确性判断均为未知；这是独立语义意见，不是5个任务执行成功。其 code-mode 关闭诊断与一次报告解析误分类均保留，修正解析没有重新调用模型。

## 最终入口究竟证明到哪一步

最终安装包、当前源码、正式冻结和最后真实模型入口的 **91个Python模块逐文件一致**。wheel SHA256：`54399600caed217f240ebbcb719d1a1a67fa4fbfbe53403e84b7758ca57b0f90`。

最后一次明确收据路径的工程证明，从真实 RPE 预检中已审阅并经模拟确认的候选开始，使用同一调用者工作簿的新副本。真实模型调用原技能和 helper，观察到 **实际内核退出0、HMAC鉴权、完整请求/工具链、输入保留、正确输出**；共2次模型请求、18,382 tokens。该证明使用明确的原 helper 命令、固定 Python 和 stdout 直接写最终文件，不提供预期行数据。它验证最终入口与执行证据；它不加入四组原生对照分母，也不代表自然语言起草已经稳定。确认身份是测试自动化，不冒充真人确认。

原先自由执行证明中，模型先把 helper stdout 写到临时文件，再复制为最终文件：业务结果正确，但当前强证据协议只覆盖 stdout 直接落最终 inode，无法补认未实际捕获的退出事件。首次定向补验又因我把 `skills/productivity/xlsx` 写成 `skills/xlsx` 失败；这一补验脚本错误及成本均保留。修正仅作用于报告辅助脚本，生产源码没有在正式冻结后修改，旧失败没有重新评分。

## 四组正式新任务

| 任务 | 实际情况 | 严格完整链 |
|---|---|---|
| 货主、发票组合去重 | 原生把已给出的键再次当成缺失；RPE模型返回文本，未按强制选择调用提案工具 | 两边失败 |
| 冷技能质检表 | 原生产物与业务oracle正确，但临时stdout再复制缺强退出收据；RPE早期一次双工具响应违反单工具协议，闭环拒绝 | 两边失败 |
| 仓点TAB去重 | 两边均给出真实TAB与正确复合键，但用了utf-8-sig；与预登记的utf-8执行参数不同。原生另有来源映射不完整 | 两边失败 |
| 会员唯一键未决定 | 两边都指出缺键、未确认、未产生业务输出；但草稿默认编码与预登记参数不同，严格整单仍不通过 | 核心拒猜行为正确；严格整单失败 |

预登记中 `UTF-8` 大小写别名可等价，`utf-8-sig` 保持不同；没有为了通过而修改候选或放宽评分。特别是缺键探针，0/4不能被解释为两边都在乱执行。三个配对具备可比运行条件，冷技能配对因RPE协议/观察失败不具备完整可比条件，因此不宣称整体质量或成本优势。

## 质量与总成本

以下只列正式样本；失败尝试也计入。阶段耗时不是整轮开发墙钟，也不能再与外层计时相加。

| 路径 | 完整链 | 模型请求观察 | 已知tokens | 阶段耗时和 |
|---|---:|---:|---:|---:|
| RPE | 0/4 | 8 | 20,741 | 160.8秒 |
| Hermes 原生 | 0/4 | 15 | 158,277 | 270.0秒 |

全轮还包括冷预检、三次独立入口证明和全部失败：Hermes 共 **51次请求观察、473,155 tokens**，用量观察完整、缺失请求结束记录为0；这不是物理网络请求或供应商账单的独立证明。Claude 两例预检另有2,348 tokens、CLI估价0.03584美元；Claude八例超时没有可用用量或估价；Codex备用审阅另有输入20,767、输出471 tokens，推理135包含在其输出分类中，金额未知。全部已知渠道tokens合计下限496,741，但失败Claude与本轮开发Agent费用未完整收集，**不能给出真实总金额**。

原预登记CLI最多2进程，因正式审阅超时，在补调用前明确调整为3；原生执行总上限仍为5，实际4次，起草仍为10次。未用完的原生配对执行名额分配给独立入口补证；没有重跑四组业务样本。详见 `budget-amendment.json`、`all-observed-costs.json` 和各自原始阶段回执。

90秒是请求I/O/stale限额，不是整个模型请求的绝对墙钟。已装Hermes还可能做transport recovery；SDK的零重试配置也不等于只发生一次物理请求。本轮51次观察均闭合，正式Claude超时仍是未解决事实。
