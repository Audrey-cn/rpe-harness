# RPE-Harness 1.6 开发与验收

本轮按原始设计溯源结论实施：保留独立 Harness，Hermes 为第一个宿主；用明确能力契约和独立验收取代执行路径中的任务分类猜测。真实技能、上下文引用与持久维护共用既有执行/验证权威，没有并入旧阿卡夏运行时，也没有增加常驻服务。运行依赖仍仅 openpyxl。

## 实际交付

- 真实技能目录支持原字节不可变快照、变更检测、冷技能发现及显式信任。首个可执行适配调用本机 XLSX 技能的原始 `xlsx_read.py`，支持 rows、sheets、formulas；目录中的其他技能不能因排名或正文声明自动执行。
- Hermes 闭环为发现 → 原生加载 → 来源上下文 → rpe_task → 独立验收。真实 API/tool IDs、完整 schema 与 SDK 观察投影、参数/来源/脚本 hash、持久 receipt 和产物必须对应。阶段错误、缺事实、冲突和无效参数保持可见；业务描述与固定约束标志分开。
- 上下文恢复使用有会话归属的来源引用，只补能力必需事实，执行前重新核对来源和时效。跨进程恢复及冲突拒绝已验证；原生长聊天的自动事实提取仍需后续宿主适配。
- 维护使用持久游标、waiting/pending 队列、语义诊断证据账本和租约，每批最多100条运行、32个提案。总历史超过100不再阻断，旧活动版本证据仍独立复查。
- 候选生成器只提出已有 CSV/JSON ABI 代码，不能审批。真实反馈库、保留验收材料和项目源码受读取隔离；候选仍经专用 oracle、证书和 CAS 激活/回滚。

## 原生对照

提前登记六个公开 XLSX 情景、每个两次重复、native/RPE 两臂，共24个会话。输入、原始 prompt、当前模型、真实技能快照和已有 openpyxl 解释器相同；按配对交替臂序。native 可灵活使用 terminal/file/skills，RPE 强制阶段工具，这个策略差异是比较的一部分。所有失败和成本均纳入，计费金额未知。

| 指标 | Native | RPE |
|---|---:|---:|
| 独立业务产物正确 | 9/12 | 11/12 |
| API请求 | 80 | 70 |
| 全部观测 token | 928276 | 583847 |
| 全部会话总耗时（秒） | 712.532 | 592.385 |

这组样本中 RPE 的观测 token 减少37.1%，总耗时减少16.9%。两个臂的 usage 覆盖完整；token 含缓存，不能据此推出相同比例的账单或计算量下降。六类简单任务、单一模型及两次重复不足以证明通用优势、长期学习收益或因果图收益。

原生评分器初版错误地要求官方 stdout 带 tool_call_id，原评分保留。补充验收用持久真实 API/model/pre/post IDs 与参数多重集核对，12个原生会话调用关联全部通过；原 helper 严格成功证明仅1个，2个为观察到调用但成功证明不足，9个没有足够严格证明。业务质量使用独立文件真值的9/12，不能把初版 gate 的0/12当作原生质量。补充统计已被另一代理独立重算。

正式实验的冻结候选 A 暴露了 RPE 工具 constraints schema 过宽的问题：模型填入自然语言要求而非契约标志。交付候选 B 收紧能力标志并返回可纠正字段错误；旧失败没有替换。两个候选的源码清单分别保留，修后公式与来源恢复另列补充验收。初次原生 pilot 自行安装依赖的成本单独保存，未混入共同已有依赖的正式比较。

初版定向驱动也误用了无 ID stdout，并把契约明确拒绝的空键 CSV 当成功夹具。其四个实际尝试和原评分保留，不能归因成 Harness 质量失败；驱动补齐调用关联和异常成本记录，有效夹具经真实 CLI 与独立真值检查，再在新登记下验证两个来源恢复会话。另5个方法回归通过。真实候选生成的两个 owned-root 不匹配预检错误亦保留，没有启动模型。

## 限制和后续优先级

1. 扩展真实适配与独立验收，再讨论增加技能覆盖；目录条数不等于可执行能力数。
2. 优先解决生成器在本机模型上的超时与提案质量。不能因为配方可自动激活，就宣称真实代码生成升级已通过。
3. 将来源引用接入真实多轮宿主历史，在严格事实来源边界内减少人工传入 context_sources；增加更多模型和真实任务对照。
4. 做多日维护观察及故障演练。当前证明的是有界持久分批与恢复机制，未部署无人值守常驻服务。

执行细节见 [todo](../../docs/superpowers/plans/2026-10-14-rpe-v16.md)及[使用边界](../../docs/real-skills.md)。所有原始测试日志、会话历史、缓存、临时数据库/解释器、凭据副本与临时进程在本轮拥有的目录内，交付只保留脱敏精简证据和公开夹具。

日常 .env、config.yaml、state.db 与两旧仓 HEAD/status 核对一致，39个测试会话均不在日常数据库。auth.json 在期间发生变化；隔离宿主禁止读写该日常文件，但目前没有把变化来源独立归因。为保留正在使用的登录状态，本轮没有恢复或清理该文件。清理范围以本轮 ownership 标记和精确进程身份为准。
