# RPE-Harness 1.8 开发与验收报告

日期：2026-10-15。交付性质：本地可用的有限寻址闭环。本地交付分支 `codex/rpe-v1.8-release`，版本标签 `v1.8.0`。最终运行源码为 `d1f4254`；其后报告、清理证明和 todo 的提交不改变这份运行代码。没有推送或发布远端。

**本轮把寻址与最小状态交接跑通了；没有证明它比 Hermes 原生更好。** 冻结正式对照暴露了接口缺陷，结果全部保留。修复后两个独立真实任务通过，仅证明最终版本在这两个输入上可用，不能替换原正式成绩。

## 现在实际做到了什么

用最初讨论的说法，链条变成：听懂当前任务 → 去统一目录找能力 → 父进程把文件、参数和要求存成任务单 → 下一环节只拿任务编号 → 执行并独立检查实际结果。

后一个环节不用重新读整段聊天，也不能重新解释“按哪列去重”。模型负责提取，目录负责寻找适用能力，执行器和验证器继续负责真正做事、检查和发布。没有再训练一个自己的分类器，没有新建学习调度平台。

| 模块 | 本轮交付 | 边界 |
|---|---|---|
| 统一能力目录 | CLI、HTTP、Hermes 共用 CapabilityCatalog，按能力和格式建立索引，快照与信任变化会失效 | 外部技能可发现不等于可以执行；当前最多2048条发现记录 |
| 任务理解 | `goal / capability / constraints / execution` 四字段，约束名称来自可信目录；未知字段和不支持条件明确拒绝 | 仍依靠 Hermes 模型解释自然语言，不保证模型永远不漏提业务要求 |
| 最小状态 | 不可变状态绑定会话、输入 hash、来源及目录；交接单只有五字段 | 不是完整聊天记忆，不可跨会话挪用，不自动猜测缺失业务参数 |
| 实际模型交接 | `rpe_understand → rpe_task(state_id) → 终态`；第二阶段实际 API 消息被替换为固定说明和交接单 | 理解阶段仍需当前原始请求；RPC大小和模型消息大小分别记录 |
| 执行和验收 | 沿用既有执行器、父进程 broker、原生身份及收据、独立 oracle、无覆盖发布 | 只支持去重、JSON空白规范化、可信原生XLSX helper检查三类能力 |
| 轻量维护 | 普通学习、记忆、技能整理和调度继续交给 Hermes；验证摘要和错误作为工具反馈 | 本轮隔离对照关闭自动变更，没有证明长期飞轮收益 |

结构化任务可直接调用 `intent prepare`，无需模型。自然语言任务使用 `hermes run --entry-mode address`。具体命令与限制见[使用说明](../../docs/capability-addressing.md)。旧路由和技能入口继续兼容。

寻址测试覆盖2000个无关发现条目，检查明确查找不扫描无关描述、模型额外目录提示不会逐条膨胀。这是结构与回归证据，不能冒充大规模真实技能库的收益测试。

## 真实测试发现并修复的三处问题

1. **工具初始化准入。** 旧接线试跑中，API已经补上工具schema，Hermes原生初始化却把插件工具全部延迟加载，调用名单里没有它们。现在仅address隔离配置使用Hermes官方 `tool_search.enabled=off`，启动即加载两个工具；原生对照保持原搜索方式。新测试实际经过 `_load_tools → valid_tool_names → validate_tool_calls → invoke_tool`，不再用直接调用handler代替真实准入。
2. **固定约束与自然说明混淆。** 工具schema原来只要求字符串数组，模型将中文业务说明、操作限制也塞入其中，父层依契约正确拒绝。现在schema枚举来自可信目录，明确每个能力只能选择自己的约束子集；完整目标和执行参数各归其字段。父层继续拒绝未知约束，不过滤、不偷偷改成正确答案。未知必需业务要求应拒绝的说明属于模型指导，不是新语义验证器。
3. **拒绝结果丢失快照来源。** 只有ready分支保存显式snapshot，合法拒绝在最终检查时用None重建目录，从而误报目录变化。现在所有理解结果都保存初始来源，包含原样None；目录、信任和摘要检查保持严格。回归覆盖合法拒绝通过，以及拒绝后撤权、目录指针变化仍不能通过。

这反映了本轮原测试覆盖的不足：接口测试与直接SDK接线通过，并不足以证明真实宿主准入和完整任务理解可用。缺陷由真实会话发现后补入验收，未通过训练或反复调整正式试题取得好成绩。

## 哪些大块仍未完成

统一目录已经存在，通用可执行能力库尚未成立：更多技能还需要各自可信adapter和独立验收，metadata不能自动变成执行权。address暂不自动恢复多轮聊天事实；来源事实需要明确提供，旧 `context_sources` 协议不能混充已经接通的新路径。

自然理解仍可能漏提、误解或省略业务要求。枚举解决了字段边界的一类错误，没有证明任意自然任务都忠实提取。长期Hermes飞轮、多宿主/多模型迁移，以及修后版本相对原生在真实任务分布中的净收益，仍缺独立证据。

后续开发应由真实任务中可复现的失败驱动，优先补必要adapter、来源与验收；本轮结束继续批量训练或重复这套正式题目，没有证据支持。
