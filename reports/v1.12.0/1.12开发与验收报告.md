# RPE-Harness 1.12 开发与验收报告

1.12 的参数合同、精确原文定位和原生观测已经实现，并完成本地安装验证与冻结对照；**稳定通过率和总体净收益的目标仍未被证明，尚不能当作稳定无人值守版**。四对正式任务中，RPE完整链通过 **2/4**，原生 **1/4**；其中一对是缺业务键拒绝探针。只看三个生产任务，两边完整链都是 **1/3**；正确业务文件为RPE **1/3**、原生 **2/3**。只有一对达到完整可比条件，`comparison_ready=false`。

本轮按冻结预算结束，没有重跑失败、改写分数或追加模型训练。最终交付保留这份负结果及具体阻断原因，源码是正式冻结的 `576ad8f`，没有在正式对照后再改生产代码。

## 本轮改动

1. 参数表达直接复用公开执行合同：CSV 分隔符必须是实际单字符，逗号是 `,`，TAB 是 U+0009；`comma`、`TAB` 或字面反斜杠 t 不自动纠正。这样减少提示与真实执行器之间的合同矛盾，也避免把模型错误藏在自动修补中。
2. 新增小型 `quote_ref` 原文定位。父进程给完整请求、最多32条非空行和已授权附件片段生成绑定内容与范围的标识；模型选择标识后，审阅页面展示逐字原文与出处。篡改、过期、跨来源、引用文字不一致仍拒绝。模型原始草稿不改写，确认和执行重新核验。它证明引用来自哪里，不证明任意自然语言语义已完整理解。
3. 原生对照补实际文件写入前后字节、真实工具调用、持久事件及调用身份的绑定。最后回复中的 JSON、终端提及文件名、伪造恢复文字不能当成完成。冷恢复复用安装的 Hermes CLI，并显式提供其模块路径，解决终端清理环境变量后无法导入模块的问题。
4. 为已经观察到的原 helper 只读诊断后缀增加有限证明语法。保留原始命令与事件；只认登记的解释器、原 helper、实际参数、技能先加载、文件字节及成功调用。旧1.11判定不变；试跑原分数也不改写。

RPE 仍是独立产品，Hermes 是首个宿主；沿用原有三种执行契约、技能发现/恢复机制、来源绑定、审阅确认、确定性执行与独立验收。运行依赖仍仅 openpyxl，没有增加常驻服务、分类器或训练框架。Claude Code 只在实验后做一次独立复核，不加入生产链路。

## 验证边界

正式实验先冻结代码和输入，再按交替顺序执行四对任务：逗号复合键CSV、带附件的冷表格技能、附件复合键TAB，以及缺业务键时应阻断的探针。两边使用同一本机 Hermes 和 MiMo `mimo-v2.6-pro`，明确附件和原文定位均对两边提供。原生侧用原生工具；RPE侧在审阅后由控制器执行。确认者为模拟语义审阅者，**没有证明真实用户确认**。4对小型本地夹具不代表所有真实业务分布。

最多10个起草宿主（含一对试跑）、5个原生执行宿主，按预登记单次预算运行；失败和超时保留，不重试替换。正式源码冻结于 `576ad8f`，85个Python模块及最终wheel字节均与冻结摘要对应。试跑使用 `46921f4`；发现原生执行证明语法过窄后，在正式冻结前修复。试跑原成绩单独留存，不重评，也不混入正式成功率。

## 正式结果与真实采用情况

| 任务 | RPE | Hermes原生 |
|---|---|---|
| 逗号CSV、复合键、001与1不同 | 原要求、执行和产物通过 | 原生写草稿、执行和产物通过 |
| 冷XLSX、附件指定模式/工作表 | 有效草稿已存；首次响应违规双发现调用，后续收尾触及五次请求预算，整链失败且未确认/执行 | 恢复、加载、附件引用和实际产物正确；原helper证明不接受分号诊断后缀，完整链未通过 |
| 真TAB、附件指定复合键 | TAB和业务键正确；五条引用同时提供了整段标识和不一致短引文，确认前阻断，无业务输出 | 宿主超时，未返回草稿；请求完成情况与用量未知 |
| 业务键尚未决定 | 正确指出缺项，无猜键、确认或输出，探针通过 | 观察到未猜键草稿、无输出；最终请求超时，完整调用证据不足，不计通过 |

这些失败不能混成同一类：RPE冷任务有协议违约和固定预算问题；TAB任务是引用冲突触发安全阻断；原生冷任务是证明语法过窄；两个原生超时缺少供应商完成回执。产物正确不替代完整调用证明，缺证也不等于业务语义错误。详细诊断和原记录SHA未变化证明在 `validation/formal-*-diagnosis.json`。

实际草稿中，观察到的CSV分隔符都是U+002C或U+0009，没有继续使用`comma`/`TAB`单词。RPE四份观察到的原始草稿共29条要求，26条选择`quote_ref`，21条完成解引用、5条不一致而拒绝；3条使用逐字引用。原生三份可观察草稿共27条要求，13条使用定位标识并解引用，14条逐字引用。来源片段成功解引用分别为RPE3条、原生2条。观察到草稿不等于完整调用已验证，冷RPE及原生缺键任务的失败状态仍保留。见 `validation/feature-adoption.json`。

试跑两边实际产物均正确，RPE完整链通过、原生因当时证明语法未通过。正式前只对观测器做一次窄修订并冻结；原试跑成绩未变。旧版本的任务组成和评分边界不同，**不能把本轮2/4直接当作相对1.11的通过率提升**。

## 独立Agent复核

实际调用本机 **Claude Code 2.1.295** 宿主，当前路由模型为 **MiMo `mimo-v2.6-flash`**，不是Claude模型。一次隔离CLI进程复核全部8个匿名ID，输出完整、输入摘要绑定通过；关闭普通工具/MCP/会话保存。匿名化只去掉显式分组标签，内容与来源仍可能提示处理方式，不能称严格双盲。

复核模型将8例均判断为“解释忠实”，但其中存在草稿或运行证据不足；这不是8例质量通过。它只将两份逗号CSV产物评为正确，其余6例产物为未知，并指出原helper调用等主张缺证。该判断既不替代独立业务oracle，也不证明宿主调用、真人确认或账单。

CLI实际耗时43.522秒，估价0.125671美元，低于180秒和0.25美元的请求限额；实际回执为 **3 turns**，未遵守请求的1 turn。累计输出2,110 tokens，高于配置请求的1,200这一数值；该配置是否只约束单次输出、每次是否生效没有逐请求证据，不能声称已强制累计token上限。没有因此重试。真实用量、请求限额及偏差全部保留，不能只报告“成功复核”。
