# RPE-Harness 1.15.2：原生收据与环境复验

本轮修复了已复现的 macOS 原生进程收据误拒。安装包的收据及相邻门禁检查通过 100 项、跳过 2 项。当前 Hermes 与旧启动、技能来源接口存在兼容缺口；真实 XLSX 烟测在预注册阶段被拦截，实际模型调用为 0。本轮不标为无人值守稳定版。

## 发生了什么

旧观察器在读取一个刚创建的进程时，先看到它还显示为 Python，随后 `KERN_PROCARGS2` 返回 `EIO`。同一 PID 和启动身份接下来显示为 `/bin/bash`；另一个 PID 才是实际 helper，且内核确认它以 0 退出。旧逻辑把启动进程的参数探测错误记到整张收据上，误拒了该有效执行。Apple 的 [XNU 接口定义](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/sysctl.h) 用于核对探测编号；竞态及发生顺序来自本机复现。

| 验证阶段 | 观察 |
|---|---|
| 原版，达到三次失败即停 | 18 次中失败 3 次；另一次带追踪的 13 次中失败 3 次，均观察到切换到 Bash |
| 只即时复查一次 | 120 次中仍失败 1 次；补充追踪确认映像更新可晚于首次复查约 2.6–3.8 毫秒 |
| 最终生产代码 | `EIO` 后最多约 20 毫秒只复查身份；旧用例连续 120 次通过 |
| 最终安装包 | 100 通过、2 跳过，包含已切换、首次采样仍旧、活进程身份不变三种回归 |

这次变更只决定一个失败采样是否已经过期。未解决的活进程错误仍阻断收据；有效收据仍要求真实 helper 的内核退出、冻结文件及产物绑定均合格。测试用例在真实同 PID 切换后回放一次旧采样，避免把测试本身的唤醒调度算入生产窗口。未延长生产窗口来配合测试。

## 本机 Hermes 的独立兼容缺口

1. XLSX 预注册发现 `xlsx_read.py` 与已登记的字节哈希不一致，原 `SKILL.md` 一致。查到的脚本差异为新增 `# noqa: BLE001` 注释；仍须单独复验并登记这个来源版本。预注册在任何草稿或模型请求之前退出。
2. 当前 Hermes `b200f5bc60` 的 `stream-json` 经网关执行，网关拒绝旧启动器使用的 `--run-budget`。仅删掉该参数不会把 RPE 审计钩子带进实际执行的进程。
3. 当前 `skill_view` 已不返回原 `_source_path`。冷技能测试用拦截式供应商替身观察到读取返回成功，但缺少旧 RPE 用来核对可信文件的字段，随后被拒绝。下一步可用 Hermes 的进程内 Python SDK 验证隔离入口，并从受控技能副本核验新版来源字段；继续校验实际文件与字节。

## 环境与交付边界

环境从依赖装齐起固定，使用绝对模块路径和不继承系统包的 venv。全量回归前、阻断的模型预检前后、清理前分别保留快照及字段差异。94 个源码模块与 wheel、安装后的模块字节一致。测试使用的包布局单独核对。上一轮模型运行环境的历史缺证没有被本轮回填，且本轮没有模型产物或成本对照。

最终生产源码的全量回归：**2188 通过、10 失败、7 跳过，另有 3 项子测试通过**。上一轮的旧式直接 inode 收据用例本次通过。全量在最后一次测试夹具同步调整前收集，生产源码与最终 wheel 相同；同步后的用例已单独从安装包核验。9 项失败涉及 Hermes 网关或技能返回接口；其中三项代表用例在原 1.15.1 安装包上也失败。另一项模拟 CLI 超时未写出子进程 PID 标记，单独复核两个配置同样未写出；该项仍保留失败，未把它归为进程泄漏。

所有记录的环境指纹字段前后一致，包括 Python、分发包集合、绝对导入路径、venv 配置、Hermes 源码与运行依赖。该证据确认本轮离线验证和被阻断的预检使用了同一套记录环境，尚无新模型执行可供比对。源码、安装包、测试原始 XML 和环境快照见 `validation/` 及 `release/`。

## 清理

移除了本轮专属临时目录中的 46,075 个普通文件（610,683,614 字节）和 1,883 个符号链接。测试缓存、临时运行历史、凭据副本已清理，专属进程为 0。656 项技能文件未变，两个旧仓库未改；日常 Hermes 的 `auth.json` 和 `state.db` 内容发生变化，归因未确认，未覆盖或回滚。此轮不宣称日常文件严格保全通过，见 `validation/cleanup.json`。
