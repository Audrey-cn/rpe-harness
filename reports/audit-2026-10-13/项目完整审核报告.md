## 对话中的目标及需要修订的理论依据

对话从量子协议、观察者和记忆连续性，经过 RPE（关系过程涌现论）的哲学讨论，最终收敛到持续学习 Agent 的工程问题。M49 将相关路线统一为 Harness 增强；M51—M52 讨论弱模型能否借助反馈和本地工具积累提高系统能力；M53 明确指出 Hermes 技能增长后的寻址退化、调用臃肿和冷门技能失联。

最关键的工程目标是：

| 对话位置 | 目标 | 应如何在项目中验收 |
|---|---|---|
| M53—M54 | 能力库扩大后仍能可靠找到已有技能 | 固定真实任务集，测不同技能库规模下的 Recall@k、任务成功率和成本 |
| M55—M56 | 下游只接收决策所需状态 | 验证目标、约束和前置条件是否保留；信息不足时可回溯 |
| M56—M58 | MCSI、分层寻址、记忆执行解耦 | 结构化接口、来源引用、补充上下文路径和逐级升级处理 |
| M51—M52、M58 | 将可靠经验固化为本地能力 | 学习前后同任务对照，验证脚本可复用且节省真实推理成本 |
| M54、M58 | 已积累能力保持可发现、可验证、可调用 | 休眠、恢复、过期、重新验证和回退机制 |
| M59—M60 | 在 Hermes 外围开展非侵入实验 | 原生 Hermes 与旁路增强在相同任务和环境下对照 |

M55 所说的“不需要完整记忆，只需要因果”，在 M56 已被修正为“完成当前决策所必需的状态、约束和因果关系”。这项修正应保留：字段少并不自动意味着信息充分；缺少关键约束时必须允许补充状态。

科学依据需要单独修订。存档前段把 Violaris 协议概括为“发送者记忆必须擦除”“单向且不携带记忆”。截至本次审核，论文 v3 于2026年9月26日修订，描述的是反计算、部分分支交换、再计算；最终观察者恢复自己写消息的记忆，并获得另一分支写在纸上的消息。因此，早期概括不能继续作为该协议的一般结论。[Violaris 论文 v3，定理1及后续说明](https://arxiv.org/html/2601.08102v3)

Altman 的五量子比特实验研究同一电路内寄存器之间的信息转移和噪声下的见证量，论文明确说明其结果不区分量子力学诠释。它不能证明宏观平行世界通信、意识理论或 RPE。[Altman 论文](https://arxiv.org/abs/2601.16004)

RPE 可以作为研究动机和解释框架，MCSI 可以作为本项目的接口名称。当前代码和实验不支持“重大技术革新已经实现”“因果图已解决寻址问题”或“弱模型加此 Harness 已超过强模型”等结论。最可信的对外定位是：研究持续学习 Agent 的能力寻址问题，建设状态驱动的旁路原型，并设计实验检验其价值。

架构文档把检索成本线性增长、每次都浏览完整技能库写成现状，目前应标为待测瓶颈假设，并注明 Hermes 版本、任务和技能库条件。Hermes 官方机制已有容量受限的持久记忆和会话开始时冻结的快照，不能把全部历史始终注入模型当作默认基线。[Hermes 官方记忆说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory/)

## 冷门实验的可信度

现有实验随机将10个技能标为休眠，再生成20个任务。它不是从真实历史使用频次或失败记录判断休眠，也没有验证长期遗忘后的恢复。

实验的 usage_contexts 和任务 goal 都来自同一份 skill_tokens；生成器还保证独有词被拆成至少两组，以满足场景匹配阈值。20个任务全部是 UNKNOWN，且每个 goal 都包含目标技能 ID。这样的任务直接给出了答案线索。[场景生成](/Users/audrey/项目/rpe-harness/src/rpe_harness/experiments/cold_skill_test.py:108)、[任务生成](/Users/audrey/项目/rpe-harness/src/rpe_harness/experiments/cold_skill_test.py:160)

| 消融条件 | 冷门发现恢复率 | 不匹配推荐占比 |
|---|---:|---:|
| 原实验 | 100% | 52.38% |
| 原图，不补合成场景 | 0% | 0%，因为没有发现结果 |
| 删除全部图边，保留合成场景 | 100% | 23.08% |
| 只保留图边，去掉全部场景 | 0% | 0%，因为没有发现结果 |

在这组任务上，图边不是获得100%恢复率的必要条件。删除边还降低了不匹配推荐占比。当前证据支持“合成场景词可以找回预设技能”，不支持“因果关系改善了冷门恢复”。

补充20个随机种子后恢复率仍全部为100%，但不匹配推荐占比在0—65.52%之间。这并未消除同源生成问题。另10个独立中文语义改写探针中目标发现数为0；这只是小规模探索性反例，不能当作整体泛化率，但说明对常见词复述与跨语言表达存在明显盲区。[消融证据](/Users/audrey/项目/rpe-harness/reports/audit-2026-10-13/evidence/cold-ablations.json)、[种子复跑](/Users/audrey/项目/rpe-harness/reports/audit-2026-10-13/evidence/cold-20-seeds.json)、[改写探针](/Users/audrey/项目/rpe-harness/reports/audit-2026-10-13/evidence/cold-independent-paraphrases.json)

报告的 false_positive_rate 实际计算 FP/所有发现，是误发现比例 FDR；对应精确率为10/21≈47.62%。传统 FPR 使用 FP/(FP+TN)，两者不能混用。即便把20×10个任务—休眠技能配对全部列作决策机会，仍需明确这个单目标真值假设，才能计算其 FPR。

更关键的是原实验主路由 Top1 和 Top5 都为0，却仍 passed=true：通过条件只要求恢复率≥50%、休眠数量10、任务数量20，完全不限制误报、主路由或执行成功。[通过条件](/Users/audrey/项目/rpe-harness/src/rpe_harness/experiments/cold_skill_test.py:365)

因此，“恢复率1.0”目前指在返回的发现列表中找到目标，不能解释为已恢复技能执行能力。返回结果还需经过有效性确认、候选选择、实际执行和状态回写。

## 基线、性能和成本结论

baseline.py 没有调用 Hermes 原生检索，而是加载技能后构造一个新的 CapabilityRouter，并把所有技能初始化为 UNKNOWN。已知任务类型因此没有可匹配技能。仅在内存中归一化旧分类后，默认5个任务仍0/5，全部返回无候选的 REASONING。这是当前代码的代理基线行为，不能说明原生 Hermes 的准确率为0。[基线实现](/Users/audrey/项目/rpe-harness/src/rpe_harness/experiments/baseline.py:61)

压力实验使用500个模拟技能、200个合成任务、3轮，覆盖11个类型。此次 Python 3.12 复跑的总体P95约0.1607毫秒，L0 P95约0.0005毫秒，L2 P95约0.4844毫秒，总体约12999次/秒。这些是串行内存函数微基准，任务还按实际路由层级筛选；不包括 HTTP、任务理解、图发现、技能执行、验证或模型调用。[复跑压力报告](/Users/audrey/项目/rpe-harness/reports/audit-2026-10-13/evidence/stress-reproduced.json)

原压力报告使用 Python 3.9.6；本次使用3.12.14。环境不同，不能将两次数字解释为项目改进。项目 pyproject 声明 Python≥3.10，而本机默认 /usr/bin/python3 为3.9.6，快速开始应明确运行环境。

L0 查表在规则命中时接近常数开销；L1 仍遍历全部技能，L2 给候选打分并排序，冷门发现还可能逐个活跃—休眠配对做 BFS。固定500个技能的单点实验不能证明大规模下接近恒定开销。tracemalloc 在技能对象生成后才启动，报告中的 index_alloc_mb 也不包含全部技能对象内存。

tokens_used 和 context_tokens_saved 当前只是默认字段，没有实际计量。零 Token 表示这些纯本地函数没有调用模型，不能推导整个 Agent 节省多少 Token。经验沉淀效率、同类任务成本随经验下降、强弱模型对照，均未形成数据。

## 建议的开发顺序和验收门槛

| 阶段 | 工作重点 | 完成条件 |
|---|---|---|
| 第一阶段 | 纠正现有入口和路由 | 测试全通过；README全部可复现；UNKNOWN正确升级；格式、能力和条件不会被通配短路 |
| 第二阶段 | 数据、API与持久化 | 安装布局可配置数据；引用往返不丢；错误输入稳定返回；重启后统计保留；索引/图一致性检查通过 |
| 第三阶段 | 重建独立对照实验 | 数据与规则冻结；独立真值；原生Hermes基线；报告召回、精确率、成功率和真实成本 |
| 第四阶段 | 实际 Hermes 旁路接入 | 一条真实任务完成从输入到产物验证及回写；有超时/回退；能够关闭旁路回到原宿主 |
| 第五阶段 | 能力生命周期和沉淀 | 自动识别需验证/休眠能力；固化一个重复任务；新会话和重启后仍可复用 |
| 第六阶段 | 规模和跨模型研究 | 多规模、多种子、跨时段/同义表达验证；相同任务下比较模型、图、MCSI和沉淀贡献 |

建议先固定一个可安全验证的任务域，例如工作表清理并保留公式。它能同时检验自然语言约束、MCSI充分性、技能选择、本地执行、产物质量和重复成本。不要在执行验证未完成时直接扩展到大量任务域。

实验应至少包含原生 Hermes、仅MCSI、仅分层路由、路由加关系图、再加反馈生命周期几个条件。冷门技能的样本要来自真实历史或独立人工定义，测试 goal 不应直接带目标技能ID。支持一个任务多个正确技能；训练/规则调优集与最终测试集分离，并在同一输入、模型、技能版本和环境下配对比较。

规模建议按79、500、2000、10000个技能逐级测量，同时保留同一真实任务集合。分别记录任务理解、路由、图查询、执行和整条链路的P50/P95，不能把纯查表时间当用户任务延迟。状态压缩需检验任务结果和约束保留率；程序沉淀需检验未见输入、错误回退、验证成本和维护成本。

在实验开始前登记验收阈值和允许的权衡，避免根据结果修改通过标准。真实任务成功率、硬约束违规数、发现精确率和回溯能力应与恢复率共同评价。具体阈值需结合任务领域设定，当前报告不把任意数值伪装成项目既有要求。

## 对项目价值的评估

项目最值得保留的价值，是把持续学习问题具体化为“能力存在但不可达”，并尝试用结构化状态与分层寻址控制选择成本。当前小规模原型已经足够帮助发现设计问题，适合继续投入验证。

工程贡献能否成立，取决于接下来是否证明：任务结果不变或改善，选择和上下文成本下降，长尾技能更可达，反馈真的改变后续选择，而且这些效果不来自答案线索或固定人工规则。关系图应被当作可检验的技术选择，MCSI 应被当作需要充分性验证的接口，程序性沉淀应以可复用产物和长期成本证明。

面试或项目介绍可以准确表述为：“针对持续学习 Agent 的技能库增长与能力可达性问题，我实现了状态驱动的旁路寻址原型，并发现了通配规则、状态充分性和合成评估泄漏等问题，正在通过独立对照与真实执行闭环验证效果。”当前不宜宣称已实现自主进化或已经证明因果图带来普遍提升。
